# 同轮记忆复用

总结模块在当前页面保留一份已提交的召回结果，来源可以是 USER 或 AI。命中发生在分词预热、数据库读取和召回之前；不新增配置、消息字段、持久化或保存请求。

## 回合与失效

正常生成产生新来源时替换缓存。当前回复的续写、swipe、原生重生成复用正文、角色与原边界，注入深度按当前聊天楼数重算。首次无缓存续写绑定实际参与查询的 AI；之后普通回复该 AI 开始新回合。quiet 和 impersonate 不消费或替换缓存，正常空结果也可复用。

显式正文编辑、来源删除或替换、较早历史 swipe、手动总结变更、影响证据装配的配置变化、切聊、禁用与缓存清理使缓存失效。删除当前回复而保留来源时可复用；后台总结、补向量及普通隐藏开关不改变本轮已采用的结果。修改保留可见楼数会失效。

群聊普通成员回复各自建立来源；末尾续写复用。整轮重生成删掉来源后重新召回。停止未完成召回不安装缓存，旧请求迟到不能覆盖新聊天的缓存。

## 生成前的失败处理

查询 Embedding 单次限时 3 秒。超时、网络错误、HTTP 408 或 5xx 才在间隔 1 秒后重试；两次可恢复失败后，拦截器中止当前宿主生成，恢复流程真正停止酒馆、等待内部空闲，再启动独立的新生成。没有轮数上限；成功前不能带失败的空记忆进入主模型。429、配置错误、其他 4xx、无效响应及未知错误当场停止并报告，不参与请求内重试或跨轮循环。后台补齐仍使用自己的退避策略。

当前实现中，非向量的召回失败也停止本次生成，不自动重跑。每次因失败阻止发送都刷新原因提示与召回日志，不使用告警冷却隐藏重复发送的失败；前台失败提示只保留最新一条，不清除其他功能的提示。成功准备时的非阻断提醒和后台维护仍保留各自的冷却策略。

恢复流程属于总结模块，只持有本次运行临时态。用户停止、切聊、编辑或停用取消整个循环，迟到的宿主准备不能继续生成。界面在换轮间保持原生停止按钮，不锁住宿主内部忙碌标志。首次失败前的查询耗时计入累计时间；累计 30 秒只显示一次 `feedback-copy.js` 定义的短提醒，不自动停止。成功或取消清理计时、提示和界面占用。

普通对话重启直接调用宿主生成入口，不模拟点击/回车，所以不重新执行发送前剧情规划。原消息及规划已经入楼；重启仅在宿主读取输入框的短暂准备阶段锁定、暂存下一条草稿，进入拦截器后原样恢复。重生成已做过的删楼不重复；群聊走宿主自动生成入口。每轮召回仍保留独立计算截止，不把它当作跨轮重试上限。quiet（包括 `/gen`）跳过自动召回和恢复；impersonate 保留召回，重启保持原类型。

骰子通过共享的请求所有者入口接收重试请求，由骰子自己创建新的 signal 并重发 `continue`。逻辑续写会话和已保存检定不变，当前宿主请求的 signal 可以被真正停止。内部换轮不取消骰子选择；用户停止或卡片取消仍取消整个逻辑会话。发起方退出后，迟到的重发调用直接完成收尾，不再启动生成，也不遗留等待中的界面占用。

记忆维护的多次失效通知合并到同一个准备任务，等当前保存结束后读取最新记忆，不逐条取消发送。显式正文、设置或记忆数据修改打断实际进行中的准备或恢复时说明原因；已取消、已完成的召回不算被打断，停止后的取消占位仅防止迟到请求重新召回。用户停止、切聊和停用不额外提醒。

quiet 在总结拦截器入口直接跳过，不召回、不写入，也不清除记忆位置。无请求身份的 `GENERATION_ENDED` 仅通知后续维护，不清除记忆，避免 quiet 结束时误清前台已提交、尚未组装的内容。下一次正常召回入口仍先清旧记忆再写新记忆；明确停止、切聊、停用等原有清理点保留，恢复流程自身的内部停止仍由恢复所有者识别。宿主的 `extension_prompts` 仍是全局槽位，quiet 可能带上前台当前或上一轮留下的记忆；与改动前一样可能带记忆，但不保证来自同一轮。不新增 filter、排队或请求结束归属机制，不承诺 quiet 的记忆隔离。

在宿主准备阶段停止时，循环立即取消，但输入保护和发送拦截保留到该次宿主调用退出，防止旧准备流程清掉用户的新草稿。卸载时取消自有宿主调用；临时拦截器在该调用最终退出时移除，不留下注册或运行状态。

## 保存与生命周期

缓存最多一份，只保留采用正文及必要边界，不保留向量、候选池或活跃检索会话。刷新后为空，不跨进程恢复。

手动总结成功保存后先使匹配原聊天及执行身份的缓存失效，再处理取消收尾；保存失败保留旧结果。切聊或同聊重载后的旧回调不能清掉新缓存。复用不增加聊天保存请求。

## 检查

稳定行为测试见 `tests/recall-reuse.test.js` 和 `tests/recall-diagnostics.test.js`。可运行 `npm run test:story-summary:runtime`、`npm run test:story-summary:alignment`及现有总结测试。

最终请求、群聊归属和宿主事件顺序需在真实宿主检查。固定接口响应只证明协议与次数，不证明召回质量或用户设备耗时。
