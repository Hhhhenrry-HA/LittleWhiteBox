# 记忆 Agent 维护：施工文档

## 1. 当前状态与文档分工

2026-09-26：P1–P5 代码与工程验证已落地。P6 固定样本、零 API 预检和调用收据已具备，但现有共享 API 凭据／额度未能产出模型结果，真实纠错质量与预算标定尚未验收；不将整个功能标为验收完成。实测范围、命令结果和缺口统一见[验证记录](./memory-maintenance-verification.md)。

[目标设计](./memory-maintenance-target-design.md)是产品语义、术语、权限、界面文案和验收口径的唯一来源。本文只记录代码落点、施工顺序、检查方法和证据，不复制维护规则或另写一份 Prompt。

当前工作区有地图相关在途改动；不清理、不提交、不覆盖它们。本文中的 OS 参考只代表已存在的机制，不将其并入本任务改造范围。

## 3. 施工落点

Agent 功能落在 `modules/story-summary/maintenance/`，多入口共同依赖的历史、失效和提交由 `modules/story-summary/data/` 拥有。按下列职责拆分，不先搭通用管理平台；文件名可在同一边界内调整，不用文件名做行为测试。

| 职责 | 所有内容 | 不能越界做什么 |
| --- | --- | --- |
| 运行编排 | 接收已提交批次、当次队列、范围、取消、状态 | 不直接改记忆，不依赖页面存活 |
| 证据读取 | 当前聊天来源捕获、搜索、分页、截止与变更检查 | 不写原文，不拿召回结果代替唯一可查原文 |
| 领域操作 | 大总结修改、锚点修改、事件合并及引用校验 | 不接管供应商，不把内部 metadata 暴露给模型 |
| 会话执行 | 草稿视图、声明工具、调用协议、覆盖结果 | 不把工具已暂存当成已保存，不创建跨重启任务 |
| 数据层提交与历史 | 基线检查、一次 metadata 确认、历史模型、锚点退役、撤销 | 不私建第二份事实库或与成果重复的审计账本；调用方不单独恢复内存 |
| 结果投影与文案 | 从记录派生 UI 结果、集中定义表达层文字 | 不持久化派生计数，不散落文案字面量 |

正式编写模型提示词和工具说明时使用仓库的 `writing-model-prompts` 技能；界面按 `frontend-design` 技能设计与实测。两份文档不提前复制将来的系统 Prompt、schema 描述或工具文案。

## 4. 分阶段施工

顺序以数据安全和可验收闭环为先。各阶段完成证据填在第 7 节；阶段完成不等于整个功能交付。

### P1：领域读写与事件合并

对应[目标第 1–3 节](./memory-maintenance-target-design.md#1-目标与用语)及[工具边界](./memory-maintenance-target-design.md#61-工具能力)。

- 定义维护读取投影、稳定记录定位和编辑操作；大总结覆盖完整业务 JSON，不漏掉 facts、弧光和别名。
- 实现纯内存草稿上的纠错、删除与完整事件合并。沿用现行字段含义，来源和记录身份只能由受控边界处理。
- 实现保留事件、引用重定向和影响集合计算；该集合供提交、索引和结果派生共用，不逐处重新猜测。
- 校验锚点内容与关系；同步处理删除后楼层统计，不能让下一次提取把已处理记录无意重买回来。
- 先以领域单测验证例 E1 的合并操作、引用完整性、无变化及未选中记录保留；是否应当合并的语义判断留给 P6，不用纯操作单测冒充模型判断正确。

**退出条件**：不调用模型即可用真实数据形状完成修改与合并，失败不污染原数据；最终保存还未接入时，不把草稿展示成成果。

### P2：保存、历史与派生数据一致性

对应[目标第 6.2–7.3 节](./memory-maintenance-target-design.md#62-草稿和成果)。

- 冻结当前总结历史、锚点和文件边界的真实 fixture；在入口完成所需格式转换，不在日常运行留两套模型。
- 为总结历史批次增加有序维护记录，定义无修改检查和有修改检查的同一成果结构；保存检查覆盖、修正差量、依据和理由，不保存模型思考或整段原文副本。
- 接入 metadata 的短提交临界区；验证聊天、来源、读写基线和取消状态。不得把调用延迟刷盘函数的返回值当成确认保存。
- 实现历史逆序恢复。重点覆盖同批重复维护、跨批旧事件修改、后续人工编辑冲突、原文删改、导入基线及别名修正。
- 串联受影响向量清理、内容保存、索引更新和缺失向量补齐。只清理与本次差量相关的派生数据。
- 对接清空、导入、回滚和聊天删除，明确各动作的维护记录处理，不改纯总结文件为隐含全历史备份。

**退出条件**：提交、保存失败和撤销均在集成边界验证；旧向量不会假装新记录有效，成果和在用记忆不会一边已保存、一边无记录。

### P3：证据工具与 Agent 会话

对应[目标第 2、5.2、5.3、6 节](./memory-maintenance-target-design.md#2-修正原则)。

- 实现有截止边界的原文搜索、分页及 U/A 阅读，记录实际证据引用；必要时抽取已有阅读代码的通用部分，禁止直接绑定管理员应用。
- 接入共享 Agent 主配置及浏览器 provider 入口；先检查已有通用执行原语能否满足需求。若现有循环包含 OS 身份和领域约束，不能原样复用为记忆管理员。
- 为两侧工具提供同一会话草稿视图；建立覆盖清单与模型判断的明确分界，读过不等于审过、格式正确不等于语义正确。
- 编写唯一来源的领域规则与工具说明；复用 P1 校验，不把业务限制只写在提示词里。
- 接入错误回喂、无进展终止、输入预算和轮次边界；用代表性数据确定数值并集中定义，不能凭其他 APP 默认值宣称足够全量。
- 用可控 adapter 做集成验证，再用授权样本验证真实工具循环；不为只接好 API 宣称完成质量验收。

**退出条件**：Agent 能读原文并完成两侧草稿操作；权限、证据边界和未审状态不靠模型自觉保证。

### P4：后台触发与恢复边界

对应[目标第 5 节](./memory-maintenance-target-design.md#5-触发范围与时间边界)。

- 在真实总结提交边界接入统一通知，覆盖手动与自动入口以及收尾失败；避免两个回调重复发起。
- 实现当前聊天运行队列与待审范围交接；新总结导致旧基线失效时，走既定废弃／交接策略而不是覆盖。
- 接入全局授权与当前聊天功能状态；设置保存只改变偏好，不主动调用模型。
- 接入显式全量复审动作；它复用同一执行和提交路径，不复制后台实现。
- 对接切聊、停用、关闭授权、原文编辑／swipe、来源删除和卸载；区分未提交取消与已发出保存的真实结果。

**退出条件**：触发次数、范围不丢失、无额外每楼调用及继续聊天不阻塞可由宿主边界测试证明。

### P5：Agent 页与维护成果

对应[目标第 4 节](./memory-maintenance-target-design.md#4-入口与用户体验)。

- 在现有设置中加入页签，开关使用既有设置保存方式；共享 API 提示直接采用目标文档定稿，转入唯一文案定义，不另写变体。
- 宿主提供只读成果投影及运行状态；iframe 打开、关闭只影响订阅与渲染，不拥有任务。
- 展示空态、保存成果、实际覆盖、展开差量及来源楼层；低频全量动作不做成主按钮或常驻参数区。
- 由同一操作记录派生计数，明确事件合并与删除／更新的关系，不能用三个底层操作包装成三个纠错成果。
- 实测手机、桌面、深浅主题及长内容。需要代表性非空记录，不能只看空页面截图。

**退出条件**：用户能找到授权和配置指引，知道本聊天改了什么以及哪些未完成；代码测试与视觉验收分别有证据。

### P6：固定样本验收与最终交付

对应[目标第 8 节](./memory-maintenance-target-design.md#8-开工边界与验收)。

- 在运行前固定错误样本、正确对照、事件整理样本和评价项，保留维护前副本及原始调用收据。
- 分别评审两套记忆，单独统计事件整理；保留误改和漏改，不能只挑成功截图。
- 检查实际原文依据、完整细节及错误边界，不以模型自报结果给模型打分。
- 若延伸到召回对比，复用外部既定协议；不要把本功能的存储修正收益直接解释成检索算法进步。
- 汇总全部阶段的范围、验证和未完成事项。未完成项保留真实状态，不把草稿、模拟调用或局部结果冒充全量验收。

**退出条件**：工程链路与真实语义结果均可复核，才可将本功能标为完成。

## 5. 最少必要测试

测试保护以下契约，不读源码做字符串／正则存在清单，不对提示词或 UI 文案字面量作内部快照。

| 风险 | 最便宜的验证层 | 重点 |
| --- | --- | --- |
| 事件碎片未续接或错误合并 | 领域单测＋固定语义样本 | 前者证明操作完整性，后者证明判断质量；不能互相替代 |
| 合并破坏引用或误删其他记忆 | 领域单测 | 保留身份、引用转换、无关项保持、非法批次不部分生效 |
| 锚点修改只更新正文不更新关系 | 领域／存储集成 | 影响集合覆盖语义、关系、统计与派生向量 |
| 维护后撤销失效 | 存储集成 | 新旧批次恢复、人工冲突、导入基线和同批多次维护 |
| 保存失败却显示完成 | 保存边界集成 | 确认失败、未知结果、取消到达保存期间、重开读取 |
| 旧向量或缓存继续污染召回 | 检索边界集成 | 同 ID 内容变化、被删 ID 后续复用、关系变化、待用缓存失效 |
| 越权读写与未来证据泄漏 | 证据／工具集成 | 聊天隔离、截止楼层、分页、证据变更、原文只读 |
| 自动调用时点或次数错误 | 宿主调度集成 | 两种总结入口、失败收尾、开关保存、无新内容、关闭、重启 |
| 模型中断或未审被当作无错 | 会话集成 | 覆盖与状态、草稿未发布、L0 缺口、预算耗尽 |
| 页面不可用或结果难读 | 浏览器验收 | 小屏页签、焦点、触控、主题、长列表、展开／返回、错误位置 |

每项新增测试先写明保护的契约、真实失败方式、现有检查为何不足与所选层级；共享 adapter 未修改时，不重复证明所有供应商行为。

## 6. 检查命令与付费边界

以下为检查入口；本轮实际运行结果统一记录于[验证记录](./memory-maintenance-verification.md)，不能照抄过去通过数。

```powershell
node --test modules/story-summary/tests/*.test.js
npm run test:story-summary:runtime
npm run test:story-summary:alignment
npm run test:story-summary:cancel
npm run test:story-summary:bundle
npm run test:story-summary:vectors
npm run test:gold-eval
npm run lint
git diff --check
```

类型检查和构建随真实修改边界选择：若确实改到共享 Agent，再执行其构建及受影响消费者检查；不要为文档或故事总结独立改动重建别人的在途地图产物。已有不相关失败单列，不顺手修。

浏览器可从[现有真实 UI 隔离入口](../tests/ui-preview.mjs)开始，但需补齐宿主消息桥与保存状态的代表性输入；隔离 UI 不能代替真实宿主取消和保存验证。

用户已授权本功能实现及固定小样本验证；不包含新的全量召回实验。本轮仅使用独立受控样本，不修改原始聊天。样本、Prompt、工具和限制通过 digest 冻结，调用日志采用独占创建，拒绝重买已有或未知结果的运行。现有失败收据保留，不能覆盖为当前预检。外部评测目录曾清理旧产物，`STUDY.json` 的历史审计不能充当新实验预检。
