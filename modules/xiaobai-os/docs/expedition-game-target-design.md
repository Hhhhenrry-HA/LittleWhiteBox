# 余烬远征

本文记录现有战斗底座与存档、资金合同。[世界与战役设计](./expedition-campaign-design.md)是待确认的新目标，尚未实现；下文“不调用模型”和单局路线描述属于当前实现，不是新战役的限制。实施新目标时逐项替换已被取代的现状规则，不保留两套运行语义。

小白主角的俯视角动作战斗游戏。免费入场、无付费复活、不下注。移动中自动攻击最近敌人，玩家决定走位、闪避与技能时机。键盘和触屏共享固定步长输入协议。

## 产品循环

内容目录提供六职业、六区域、十二位独立首领、六十件遗物与十二套永久外观。职业、数值、区域编排分别由 `ids.ts`、`content.ts`、`relics.ts`、`outfits.ts` 拥有；人类可读文案集中在 `copy.ts`。显示层不另定战斗或费用规则。

每局从分层区域池经过三片区域，每片五个节点。进入新局时固定区域、首领和随机状态，刷新不重抽。普通房采用肃清、追猎、守护、封印、坚守和交叉火线目标：守护可因烽火被击破失败，封印必须亲自占点，坚守收缩安全范围，追猎增援不会等待，交叉火线要求换位。沿路可选择精英、篝火、祭坛和行商。

职业围绕近身破招、远距选位、蓄能爆发、背袭进出场、随从指挥和阵地部署建立。基础生存循环不依赖抽到特定遗物。远程只在实际开火动作中减速；敌人结合追击、锁定预瞄、封路和支援施加压力。预瞄在蓄力开始时锁定，改变方向可以躲过，不追踪玩家到最后一帧。

契约使自动补召使魔，主动共鸣负责治疗存活使魔、强化伤害与攻速，并诅咒目标。强化窗口由角色的 `resonance` 唯一计时，期间补召或全灭后重召共享剩余时间；使魔不各自保存强化倒计时。此战斗状态进入检查点，换房归零。施法举起展开的契约书，使魔的强化形态与技能旁倒计时共同反馈，减少动态效果时仍保留形态与状态。

遗物使用职业适配及触发来源筛选，多元素组合须同时具备各元素来源。六个自由槽，不强制防御槽。章节逐步开放强化等级，首领奖励可提前获得下一章等级；强化不占新槽。精英与首领提供更多选择，并优先给出更多已有遗物的强化。行商优先出售定向强化，也提供新遗物和生命补给；可多次消费直到主动离开。领取组合遗物不能同时换掉它唯一的触发来源；替换后店内失效的强化或组合退出，不重新抽取。局内碎晶不能兑换钱包货币。

长期成长是职业、首领成就、构筑发现和外观，不出售永久战斗力。首次成就的发币有上限，重玩不无限产币。衣橱区分试穿、拥有、购买和装备；难度独立设置。试穿可旋转和预览动作，不改变正在进行的远征。已启程的穿搭随本局保持，新装备在下次启程生效。

## 领域和存储边界

功能由 `apps/game/expedition/` 拥有，自带模型、命令、存储、资金、Host、客户端和画面。仅从 Game module、production runtime、room catalog 注册。无新增依赖，使用已有 Vue、Three.js 和共享 `brand/mascot` 母版；不复制另一套小白。

战斗分为几何与事件、伤害触发、职业动作、小怪、首领和房间推进。模拟不访问 DOM、墙钟、网络、模型或存储。浏览器即时运行同一规则，Host 从已确认状态重放压缩方向、闪避、技能输入；不接受客户端伤害、生命、随机或胜负。输入总帧数有上限，掉帧不加速。它保证协议和资金一致，不声称防止本地自动化或用户编辑自己的存档。

用户级 `expedition` 分区持有跨重启必要的活动局、已展示路线/奖励、遗物等级、区域组合和战斗检查点。有限战绩册保留已结束的局；总胜场独立计数，因为有限记录不能还原终身总数。遗物发现也是长期事实。

首次成就收据与外观购买收据是解锁的唯一来源，不另存库存或奖励合计。余额唯一来自 Economy。奖励和授予外观/扣币在同一个事务提交，业务收据与所属流水双向核账；重复 actionId 不重复发币或扣款。未知结果冻结并确认原候选，不重抽、不另购。真实已确认钱包不因升级而补款、倒扣或清空。

试穿、面板、按键、未确认输入、音效、暂停和镜头只活在当前运行。隐藏、失焦、离开或故事生成时暂停。正常暂停提交剩余输入；意外关闭恢复到最近已确认检查点，不承诺保存未确认帧。

## 聊天完全隔离

游戏不读取聊天正文、不调用模型、不注入 Prompt，不向聊天或记忆写战报、穿搭、角色设定或剧情。不提供主动或自动聊天分享，不让聊天角色回应游戏，不根据聊天生成敌人或关卡。

唯一经济连接是已有 Economy 钱包；外观不进入按故事保存、会影响回复的 Shop APP 库存。聊天身份和生成状态只用于请求隔离与运行调度，不是游戏内容来源。

## 显示与操作

画面保留斜俯视微缩遗迹基础。各区域以庭院、月潮、王城、熔炉、霜港和书库的建筑轮廓区分；首领与小怪各有可识别形态。套装改变头饰、服装、肩饰和背部构件，不只是披风换色。

`scene.ts` 管场景与镜头生命周期；`scene-kit.ts` 管共享几何和材质；`scene-world.ts` 管静态建筑；角色、首领与服装由各自显示模块构建；`scene-effects.ts` 投影危险、弹体、随从与房间目标。衣橱使用同一小白和同一套服装模型。

镜头朝向唯一在 `visuals.ts`，输入入口把屏幕方向变换为世界方向。手机近取景配合屏外敌人指示。预警按实际长度、宽度、半径和安全内圈显示，减少动态效果不隐藏危险。显示层不维护另一套生命或计时。

摇杆由 `joystick.ts` 管理当前手势和触点捕获：第一触点独占拖动，额外触点不能改方向或清空它，技能指独立；松手、取消、失焦、换房和卸载释放捕获与移动量。战斗初始化在控件可交互前完成，不在下一显示帧清掉新按下的输入。触点、缓动和 GPU 材质都只属于当前界面，不持久化。

盾牌使用带厚度和倒角的实体轮廓，护盾使用全身薄壳与受击高光，二者不混用形态。姿态缓动不延迟实际格挡、命中或输入判定；减少动态效果仍保留即时可辨的防御和强化形态。共享几何与材质由 scene kit 释放，护罩专属材质由护罩对象随场景释放。

静态建筑按材质合批，几何和特效复用；离开释放 GPU 资源。暂停战斗与静止路线页不重复绘制。画面或声音失败明确提示，不静默换成文字游戏。声音使用本地 Web Audio，默认关闭。

## 升级与删除

旧三职业格式已被用户实际使用。其类型与校验冻结在 `migration/v1-*`，只在解析入口转换；真实旧服务生成的 fixture 验证奖励、记录与进行中检查点。运行时只认识当前模型，不带旧战斗分支。

六职业的 v2 检查点格式冻结在 `migration/v2-types.ts`，由 `upgrade-v2.ts` 在读取入口转换：共鸣剩余时间取仍存活、未到期使魔的旧强化时间最大值，清除使魔个体上的旧计时；炮台和影子的等级不变。无法从旧数据证明存在的强化不推测补发。转换后统一校验当前格式，旧奖励身份、进度与钱包不变。真实旧模拟生成的共鸣中途存档覆盖此边界；仅在明确不再保留对应存档导入时退役转换器。

旧成就幂等键、金额和流水不改；原披风映射为对应免费套装；遗物转为一阶，并补齐适配内容池，不重抽已展示奖励。旧版错误分配给长剑的猎星镜在升级入口转为剑士决斗誓印，避免保留一个无效槽位。

删除功能前先由用户明确进度、收藏和已购权益的丢弃或导出策略，再删除目录、三个注册和所属分区。已有资金流水保留。聊天清理不删除用户级权益。

## 验证边界

最便宜的规则测试保护输入重放、职业动作、危险判定、房间目标、掉落适配与满格强化；事务集成保护奖励、购买、失败与未知结果恢复、跨重启和聊天切换；旧版真实 fixture 保护一次升级。实际 Three.js 测试检查模型与几何边界，不读源码做存在性断言。

全 OS 类型、lint、测试、构建之外，必须看真实浏览器的营地、战斗、奖励、行商、衣橱、购买和恢复，覆盖手机、短横屏、深浅主题、键盘与触屏。策略模拟用于找漏洞，不冒充真人胜率或乐趣验收。交付检查的临时日志和测试数量不写入产品文档。
