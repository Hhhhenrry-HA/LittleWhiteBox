# Atlas 通用空间地图：施工文档

状态：S0 已开始，基线已检查，待冻结旧格式后进入 S1；详见第 6 节。新增功能与验收均未完成。本文件不记录推测性的通过结果，也不把已有 Map／Scene 的测试成绩算作 Atlas 升级成绩。

规格唯一来源：[最终设计](map-atlas-geography-design.md)。本文只负责当前代码落点、施工依赖、检查方法与验收证据。范围变更先改规格，施工计划引用对应章节，不另写一份空间契约。

## 1. 交付与非交付范围

本轮施工完成的标准是最终设计第 10 节全部必要验收有证据，不是“森林能显示”或“工具可以调用”。

- 全部空间事实继续进入原 Map 分区；不建立试验地形分区、浏览器本地地图副本或长期双模型。
- 自然、城市、海洋、人工结构、太空与幻想空间按同一实现交付，不拆成未来题材包。
- Scene 内部、维护触发和存储协议保持既定边界，详见最终设计第 9 节。
- 本文落盘不授权操作用户真实地图、发布、推送或发起付费模型调用。实现时区分隔离 fixture 验证、真实存档样本与真实模型验收。

### 拟新增的职责位置

以下是计划位置，尚未创建；实际拆文件只围绕列明职责，不建立通用地图框架。

- `domains/map/space/`：空间类型与语义、框架转换、空间校验、Atlas 浏览投影。各职责独立，均不依赖 Vue、SVG、three 或工具回执。
- `domains/map/upgrades/`：受支持输入格式的冻结定义及独立转换；只由解析边界调用，不被普通投影或 renderer 导入。
- `apps/map/tools/atlas-spatial-compiler.ts`：把高层空间意图转换成候选修改，接入统一关联组；不能自己再保存或复制领域校验。
- `apps/map/ui/atlas/`：空间图层编排、几何／掩码适配、材质和稳定装饰；不拥有存储、地点层级或到访推导。
- `tests/fixtures/`：当前工具输入样例与真实历史存档样本分开标识，不能拿手写的当前输入充当历史版本证据。

具体 Schema 字段和上限在 S1 的领域定义中集中落定，由类型、校验及两个工具消费者引用；本文不预先复制一套 JSON 接口。

## 3. 施工顺序与关卡

顺序为 S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7。可以做阶段性本地验证，但不能发布半个新模型，也不能把未完成项目转成“以后再拆”。

### S0：冻结输入与复核基线

- [x] 检查 dirty worktree，登记本次可改范围，保留无关用户修改；不回退已有地图修复。
- [ ] 确认所有 Map 解析、导入、序列化入口，以及正常维护、重建和管理员的调用链。
- [ ] 按最终设计第 7 节冻结现行旧格式及字段契约，登记类型、校验和容量边界；不以某几份样本反推支持范围。
- [ ] 为冻结格式建立结构与边界测试，覆盖直接父级坐标、嵌套局部坐标、无坐标地点、Scene、到访事实和满容量数据；测试构造输入与用户补充存档明确区分来源。
- [ ] 运行第 4 节适用基线检查，记录原有失败与环境问题，不能计作本次新功能结果。

关卡：现行输入含义与调用边界有证据，能够依冻结格式定义完整转换；不猜测旧坐标关系。真实存档的补充确认遵循最终设计第 7 节，不阻塞施工。

- [ ] 建立当前空间模型与集中语义定义，保留地点／路线身份；框架、空间边界、空间要素及必要关系落在 Map 领域。
- [ ] 明确地点位置、真实占地、线路几何之间的引用和唯一所有者；清除重复几何存储方案。
- [ ] 实现框架正逆／组合、引用与环检查、几何合法性、容量与数值校验；普通空间不依赖题材专用数据模型。
- [ ] 更新空 Map、解析、序列化及领域编辑类型；集中引用格式版本和约束，不在多个消费者重复常量。

关卡：冻结旧格式的结构与容量边界测试能经入口转换、保存和重读，保留事实及失败路径断言通过；非法输入不发布半个新模型。没有该关卡，不接用户实际存档做渲染试验。

- [ ] 将地图包含、所有权、坐标、承载和目的地关联分别处理，不因“共享同一地图”把所有独立项绑死。
- [ ] 完成 owner 删除、目的地解关联、存活框架引用和承载引用检查，复用既有 staging／保存。
- [ ] 对正序／逆序、非法必要前提、独立成功组、无变化和同轮修参检查实际数据及结构化回执。

关卡：关联失败不留半成品；跨区源对象与独立合法组不被误删或回滚。不能只测试编译返回成功而不检查保存后数据。

关卡：同一地图事实只有一份浏览投影，世界／地区结果与真实框架一致，UI 不再另算成员和空间位置。

## 4. 检查方式

### 自动检查

命令从仓库根目录执行，依据当前 [package.json](../../../package.json)。施工时先做相关测试，交付前再做全量；文档整理本身不触发生产构建或真实模型请求。

```powershell
npm run test:xiaobai-os
npx vue-tsc --noEmit -p tsconfig.xiaobai-os.json
npm run lint:xiaobai-os
npm run lint:imports
node scripts/check-garbled.js
npm run build:xiaobai-os
git diff --check
```

新增或修改的 JavaScript 测试另用现有 ESLint 检查对应文件；不自动修复无关文件。

- 新测试先说明保护的契约、真实失败边界、现有检查缺口和最低有效层。
- 逻辑与几何用单测，工具／转换／保存用集成，挂载与关键交互用真实组件浏览器；不跨层重复证明内部算法。
- 断言数据、位置、选择、事件、语义标识和保存结果，不断言人类文案或读取源码做存在清单。
- 禁止只验证返回码、不验证最终 Map；按最终设计第 7 节检查格式支持，并分别记录构造测试与真实存档补测结果，不能冒称已执行未提供的样本验证。

### 浏览器与视觉

复用 [生产组件验收环境](../../../output/map-production-check/README.md)，扩充工具输入 fixture 与验收入口，而非搭建第二套地图实现。

执行最终设计 A／T 项时记录桌面、390px、320px、深浅主题及实际浏览器版本；检查首次进入、增量更新、缩放／全图、返回、搜索、未定位、错误态和卸载。截图必须来自正式组件，触摸模拟与实体 WebView 结果分别标注。

除视觉核对外，记录浏览是否产生维护请求、事实是否变化和视口是否跳动。画面与测试结果共同判定，不能仅靠截图文件存在或自动断言全绿。

## 5. 真实模型验收

目标是证明工具分工让 AI 可以持续维护通用空间，不是证明它能输出合法 JSON。

- 覆盖最终设计 T01—T06；每类包含首建、保持已有内容的局部修改，以及涉及关联关系的后续调整。
- 保留自然语言输入、原始工具调用与回执、最终确认的 Map、截图及前后差异。不得手修坐标后称为模型结果。
- 分别检查空间合理性、题材表达、工具可用性、增量稳定性与数据安全；报告每类完成与失败，不只给一个总成功率。
- 正常维护与管理员至少分别完成一次涉及新空间内容的真实读改回环；不能只让一个消费者走模拟链路。
- 记录模型／供应商配置和调用成本信息，但不把密钥或敏感配置写入仓库。
- 使用获准的独立测试聊天和既有调用流程。未授权、不具备环境或未执行的项目保持待验收，不自动消耗模型额度或修改真实聊天。
