# 云上叠叠屋：施工与初审

合同唯一来源：[目标设计](./stacking-game-target-design.md)。验收证据只维护在 [验收与终审](./stacking-game-verification.md)。

## 初审（2026-09-28）

- 当前工作区无 stacking 实现/存档；此前中断没有残留本任务进程。已有默认 Playwright 会话不是本任务所有，不关闭或复用。
- Moving 已有独立用户级原子事务范式；Game 的旧赌局仅验证 `game:`，Moving 验证 `moving:`，新功能用 `stacking:` 隔离，不改旧玩法语义。
- `additionalPartitions`、`storeFor/filesFor`、Economy capabilities 已足够；入口 `GAME_ENTRIES` 支持 standalone，保持懒加载。
- 已核对用户的声音持久化链路与默认开启，不回退；新声音开关有独立设置键。同一设置入口保留旧值。
- Three.js 不是物理引擎。采用明确的承托/重心模型和整数落点，表现层不得自行决定胜负；累计楼高不导致无界刚体开销。
- 最大风险是“全部对中就能通关”与“模拟随机所以莫名倒塌”。实现初批就实验四类房型、配重救局、迟早失稳、可行路线，不靠装饰弥补玩法。
- 实验必须先测随机题认证耗时/失败率，以及简单落点策略和误差策略的收益。通过不代表真人好玩；浏览器实玩要另审。
- 渲染预算、游戏时钟与保存确认分开。连续吊运需要绘制，但后台/菜单/图形故障必须暂停；自适应不能改变判定或起落速度。
- 工作区绘图、摘要、README、pet 文档等改动属于用户，避开；构建不回滚其他源代码。无提交/推送授权。

结论：边界可施工。没有需要新依赖或外部权限的阻碍。先实现并验证规则/认证，再接钱包/UI；任何合同缺口不得用缩小目标代替完成。

## 施工批次

1. 规则规格、四房型、整体承托重心、确定性吊运、有限种子生成/合法路线认证；测开场非必胜、配重挽救、门槛与收益策略。
2. 用户分区、当前局/历史最佳、收据和钱包原子事务；未知/拒绝恢复、重复防重、付费重开限制、结算一致性。
3. Host/client 身份与生命周期；Game 独立声音设置、注册入口，不共享不同领域的规则。
4. 原生 Three.js 云海/吊车/房屋/住户/灯光/晾衣绳、动态预算与资源释放；清楚的触屏/键盘输入、阶段收工和留影。
5. 现有检查、经济/恢复集成、真实浏览器全流程与窄屏/放大/触控/图形失败/资源检查；修真实缺陷后再跑对应检查。
6. 逐条终审目标，以现有文件、结果、账本、截图对应证据；清理自己的测试进程，交付而不发布。

## 当前状态

目标文档、施工文档、初审、实现、终审五步全部完成。逐项结果、截图、复跑入口和验证边界见验收与终审文档。

## 施工发现与定点修正

- 累积重心规则、四种实体轮廓及种子认证先通过纯逻辑实验，再连接钱包，没有将视觉动画当判定。
- Game 自有分区、交易命名空间、Host/client 入口及声音键保持独立；旧三种赌局类型和 Moving 的领域/声音/渲染没有改写。
- 实景审查移除了重复标题、放大空态建筑，修复结算镜头尚未拉远时留影裁楼顶；按容器高度处理横屏，而非只看浏览器宽度。
- 客户端普通读取不能抹掉未确认操作；硬刷新会丢 Host 内存候选的问题，以功能自有、单条待确认操作记录解决。持久化必要性、所有者、生命周期、失败和删除规则已补入目标文档，不扩充核心协调器。
- 浏览器使用真正 Shell、Game Host、用户事务和 Economy，仅文件端口换成内存。满楼另有真实点击落下的时钟控制验收，不只准备结果快照。
- 先运行构建再检查导入路径；曾并行执行导致 lint 在构建清空 dist 的中间时刻误报缺少 Host 产物，重跑按最终构建检查，不将其记为源码缺陷。
