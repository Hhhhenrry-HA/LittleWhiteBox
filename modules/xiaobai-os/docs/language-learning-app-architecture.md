# 语伴：实现架构与验证边界

## 1. 文档分工与功能边界

[产品设计](./language-learning-app-target-design.md)是用户体验与业务要求的唯一来源。本文只记录当前实现的职责、接缝和验证方式，不保留分批施工日志、旧版界面基线或阶段测试数量；历史决策从 Git 历史查找。

语伴由 Learning 自有领域、应用、存储、Prompt、工具和 UI 组成。它复用宿主上下文、Agent Capability、Tavily、TTS 和 Economy，不拥有主剧情、私信或四次元壁的会话。没有新增依赖、通用教育框架或后台任务队列。

聊天的 learning 分区保存稳定 ID 的搭子会话与当前选择；learning-workbench 用户分区按语言保存教学对话。两边仅保存交流正文、各自摘要、访问范围与学习引用，工具轨迹及在途状态只在运行内。奖励政策由 learning-rewards 分区管理，已到账资金只认 Economy；学习完成凭据不是第二本钱包。

工作台同一语言的存储按资料访问范围保留记忆片段；读取时只合成当前故事可访问的交流与摘要，写入不覆盖其他故事的私有片段。片段不是另一套人格或课件副本，只用于保持已有资料的访问边界。当前段落审阅在历史压缩后仍保留一份关联原答的正文，供阅读页重开恢复，不再重复回放进模型历史。

账号身份、运行时 chatIdentity 和持久故事 osId 各司其职。显示名不是任何一种持久身份；换卡不会复制语言档案，旧卡私密材料不能成为新卡模型输入。

## 3. 持久状态、保存与删除

长期事实及其产品理由见产品设计 §4。当前文件外壳和写入容量由 [storage/document.ts](../apps/learning/storage/document.ts)维护，结构由领域解析器校验，不在文档再复制字段清单和容量数值。

语言档案拥有当前课程 unit、独立复习题组 review、学习项与完成凭据。修订作为关联原答的另一份尝试保存；批注引用对应原答段落和精确词句，知识项通过 itemId 关联；范文不是用户尝试。学习阶段只有一个派生入口 [stage.ts](../domains/learning/stage.ts)，不另存步骤号或进度百分比。

### 保存边界

- 首次读取与明确刷新访问宿主文件，正常读和重开课堂复用已确认版本。缺文件与坏文件分开处理，错误不能初始化覆盖。
- 仓库串行处理写入。明确上传成功确认候选；响应丢失才核实原候选，不把网络异常当作未落盘。
- 未确认保存保留原确认视图和精确 commitId；核实、重试原候选、采用服务器版是不同动作。只有原依赖仍有效的等待保存正文可以接回。
- 语伴选择及私聊属于聊天 sidecar，工作台对话属于用户分区，各自的保存状态和恢复入口独立于 Learning 用户文件。核实使用文件协调器的只读恢复，采用服务器设置是明确动作；确认语伴改变后才清理对应交流，同一语言的工作草稿保留。
- 清空回执未知时，runner 先退休本地旧历史，runtime 仅在运行内保留原会话标识以完成确认恢复。核实或采用服务器版后重新接续实际保存状态，不重发模型请求，也不将恢复应用于已切换的另一会话。
- 用户实际揭示的帮助允许与工作任务保存合并，但只合并相同单元、相同题目及其实际材料的追加曝光事实。[merge-exposure.ts](../domains/learning/merge-exposure.ts)还保留等待原答落盘期间新增的读写讲解及作文题，不合并目标、原答或任意课程修改。
- 后续读写准备在仓库写队列内，对最新确认的同一篇文章定向追加内容；已发布正文和既有题目必须相同。它不回放开始备课时的整份快照，因而不会覆盖并行提交的原答、帮助条件或笔记。退出或更换文章后迟到结果作废。
- 宿主上传没有服务端 CAS。本实现不承诺多设备或多标签同时编辑；不增加锁文件、心跳或自动对账。
- 整页重载只恢复服务器上的长期事实。未提交草稿和未保存模型候选不承诺恢复；页面关闭前对真实未提交编辑提示风险。

### 当前格式与旧格式入口

本次不改变学习事实文件，不清空现有作文、学习项、排程及完成记录。已发布的语伴选择格式由 [companion-v1.ts](../apps/learning/upgrade/companion-v1.ts)冻结，在选择服务的读取入口一次转换为稳定会话；旧运行内混合历史不伪造成两份持久记忆。

独立会话最初的引用式格式由 [memory-v1.ts](../apps/learning/upgrade/memory-v1.ts)冻结，真实样本为 learning-memory-v1.json。会话存储边界从仍存在的来源一次派生权限，交给 runner 的始终是当前格式；新保存直接携带交流与摘要的访问范围。旧格式已因来源丢失而失效的交流不能推测所属故事或公开恢复。

运行时只认当前格式。以下是本次保持不动的既有学习文件升级规则；已发布 v1 文件在 parseLearningDocument 入口一次升级：

- 保留语言设置、语法/词汇学习项及其证据；缺失的排程历史不推算，按升级规则重新开始。
- 不保留旧课程、其他技能学习项和旧完成凭据，包括其未领奖励。
- 日常业务不携带 v1 分支；兼容对象仅为这份已发布文件格式。规则与样本在 document 及 [learning-storage.test.js](../tests/learning-storage.test.js)，不为旧 UI 或工具留兼容壳。

删知识项、原答、课程、语言和全部数据分别走应用服务，处理依赖反馈、排程及仍有其他引用的证据。conversation-references 从本轮实际资料派生访问范围，交流还继承其所用历史与摘要的范围；该权限随记忆保存，不再用来源是否仍存在来决定记忆是否有效。显式删除仍按引用清理相关交流与摘要；替换文章不走对话删除。清空 Learning 不撤销 Economy 已到账流水。

功能退场的数据策略是删除 Learning 自有数据，不迁入四次元壁。移除步骤：取消所属运行；一次清理 Learning 用户文件、用户分区 learning-workbench / learning-rewards 及各聊天的 learning 分区；删除 Learning 注册与目录。共享配置、TTS 公共能力、Economy 已到账流水和其他领域数据保留。现有 module.clearData 仅定义聊天分区清理边界，内核没有应用卸载命令，不能把删除聊天当作全用户学习数据卸载。

## 4. 工作台任务、交流与能力

workbench 与 companion 显式分派到两个 teaching 实例，分别拥有消息、错误、摘要和取消。工作台不调用角色上下文适配器；搭子只有公开资料读取及 LearningRequest 委托能力。工作台动作和 LearningRequest 委托进入相同 learning/* 原生操作。委托引用用户当前明确指令；替换未完成课程等待确认。普通问答不自动成为作答或设置变更。

[agent/access.ts](../apps/learning/agent/access.ts)区分交流用途与训练用途，并选择本次目标单元；[tool-contract.ts](../apps/learning/agent/tool-contract.ts)中的同一许可集合用于模型请求及工具执行，文档不另维护一张工具权限表。

- 备课/批改可以与交流并存。停止聊天不停止工作任务，停止工作任务不清掉聊天。
- 冲突的原生操作和委托明确拒绝，不隐藏排队。主动机会遇到忙碌直接让位。
- 交流提交的原话与帮助条件取消息到达时的依据，不使用模型改写后的答案；随后回复里的提示不能倒改这次原答的条件。
- 复习提交后的阶段推进归 runtime，而非可能已卸载的复习组件。
- 阶段请求只取得当前待评原答或修订，包括争议后重新待评的答案；已解决反馈不因恢复操作重复评估。
- 原答先确认，再调用相应教学任务。未确认的用户输入不能成为已提交成绩。
- 读写入口在模型会话之前检查共享 Tavily 配置；缺配置时暂存本次选择意图，等用户明确选原创或进入设置，不写入学习档案。继续已有文章不做联网检查或重新选材。
- 读写准备拆为取正文、按顺序补知识、出作文题。正文由 lesson 编译器建立固定总结题；后续工具只接收所需内容，不能写原答或改正文。provider-loop 收到有效内容即结束该步，不追加收尾调用。补充任务使用当前训练事实，不重放先前备课的工具历史。
- 准备任务不占用用户提交和交流的运行通道；暂停准备不取消并行聊天或总结审阅。运行标记和取材选择只在当前会话存在，恢复依据仅是保存内容中的缺口。

## 5. Prompt、资料与发布

产品职责见产品设计 §14。代码归属如下：

- [prompt.ts](../apps/learning/agent/prompt.ts)：两个独立主体的身份、共享学习事实、当前任务指引及唯一收尾规则。普通聊天不装配备课或结课任务指令。
- [tool-contract.ts](../apps/learning/agent/tool-contract.ts)注册学习工具；独立读写准备工具位于 [preparation-tools.ts](../apps/learning/agent/preparation-tools.ts)。用途、返回值、字段及限制归对应工具所有，数值引用领域常量。
- [context.ts](../apps/learning/agent/context.ts)：当前请求实际资料；[data-projection.ts](../apps/learning/agent/data-projection.ts)与 LearningRead 共享读取投影。
- 人物表达复用 character-dialogue 的真实共享规则；提示词不进学习文件，不提供用户覆盖配置。
- 历史整理仅消费已发布交流；当前工具续跑按 Agent Core 协议保留必要载荷，不将其当成已对用户说过的话。

每次陪聊、答疑或主动陪读都带完整公开材料和实际设置；锚点只定位，不替代全文。复习准备/批改及其原答复核读取 review，不能误用相邻文章。段落审阅只取得公开题目，正式评估另有对应答案规则；已归档或尚未公开的评估必需材料只补在该次评估 focus，不重复注入当前全文。

review-prepare 的输入及输出范围由 access 中的学习项／证据投影共同决定，runner 与工具会话使用同一规则；公开复习的资料注入和 LearningRead 均不读取故事私有内容。

Core 负责真实协议终止；Learning 负责发布和保存依赖。工具成功仅表示候选通过本次校验，不表示保存或发布。停止/失败后已经确认的事实不倒退，未发布候选不复活。

普通对话不依赖工具声明，文字直接显示；保存成功只决定能否重开接续，不决定已收到回复能否看见。正式提示、答案和文稿由原生 reveal 操作记录曝光；引用文章问意思不触发该操作。质量边界见产品设计 §6.2。

历史压缩必须完整、有缩短收益且未过期。并行任务只在原历史前缀和摘要仍相符时替换所属主体的历史；不能删除另一条正在运行的交流。当前材料和本轮必需原答不被压缩为摘要。

## 6. 阅读、复习与双空间生命周期

具体体验见产品设计 §6、§8；这里固定实现边界：

- 学习助手在工作台内按需展开，复用带 target 的 LearningConversation；关闭恢复文章位置。聊天与工作台分别持有轻量草稿，界面卸载不取消任务。
- 读写在 LearningReading / LearningGrading 直接完成。专项题保留原生控件；LearningActivity 只在打开时挂载，不承担主读写流程。
- 原文引用由 reading-selection 校验 UTF-16 偏移与精确原句，兼容无空格语言和跨码元字符；打开引用不发送模型请求，不覆盖已有聊天草稿。
- 写作、修订、设置、聊天与专项草稿由轻会话保存；保存回执只退休匹配的提交，不清空等待期间的新输入。
- 当前学习单元及复习题定位同属轻会话。LearningApp 从工作区的滚动、交互及切换取得定位；显式引用覆盖默认定位，重视图卸载不丢失追问目标。Host 校验目标仍是本故事可读的当前课或复习组，再由 access/context 选择同一公开投影。
- 段落审阅由 teaching 按原答 ID 保留已发布对话对象的引用，工作台投影与聊天使用同一份内容；历史压缩不清掉当前作答的审阅。原答删除／重写时清理对应引用；已完成审阅通过会话记录的原答关联恢复，不复制正式评分。
- Reading 的当前查看页属于轻会话；主动工作台动作由 LearningApp 导向对应结果或复习题组，不把模型状态更新当作强制导航命令。复核显示实际 revision，原稿标记始终只代表原稿。
- learning-editor 在重挂载时恢复光标和编辑器滚动，不自动聚焦软键盘。页面与消息滚动在返回时恢复；看旧消息不会被新回包拉到底部。
- 窄屏转场期间两侧短暂共存，结束后卸载非活动重视图；快速反向只认最后目标。宽屏比例调整保留两侧可阅读宽度，减少动态效果时即时切换。
- 陪读调度由轻外壳持有。[companion.ts](../apps/learning/application/companion.ts)拥有随机机会范围，[use-learning-companion.ts](../apps/learning/ui/use-learning-companion.ts)接入可见性、输入、菜单和任务状态；无后台补发。
- 一次安静结果不写空消息、不追加请求。工作台完成结果不写成搭子发言，也不为庆祝另发模型调用；搭子下一次请求读取公开结果。
- 学习动态从当前请求的进度与已脱敏消息派生，工作台和会话使用同一组件；运行时展开、结束后收起可回看，成功/失败步骤都保留。进度只属运行内，不新增长期记录或模型请求。同步命令完成时发布最终状态，避免中间推送令界面丢弃语言选择等操作的回执。
- Learning 的 UI 请求统一在 use-learning-state 形成 JSON 数据快照，再交给 FrameBridge；引用选区、答案和修订中的嵌套响应式对象不跨 iframe。FrameBridge 区分发送失败和回执超时，并释放失败请求的计时器。发送失败保留输入，不要求重载；回执未知只提供状态核对，不自动重发。其他后台任务的推送不能抹掉本次失败提示。
- 聊天重试由各自 teaching 实例保留本轮原请求（消息、引用和练习定位），只存在于当前会话；失败或停止且尚未进入保存时，Host 投影该条消息的重试权限。重试替换同一轮回复，不重复用户气泡或把失败轮回放成新的历史。新聊天、换语言/角色/材料、清空或结束实例后旧重试失效；保存未确认仍走原候选核对，不重新生成。
- 备课的失败原因与恢复按钮归同一动态卡；停止首次备课也保留入口，重试沿用原来的联网/原创选择。成功正文和补充内容按既有准备阶段保留。联网过程只投影允许的错误分类及 HTTP 状态，原始响应、地址、凭据和正文不进入过程元数据。
- 语法批注直接打开同一知识项及证据；生词收藏、学习本和 SM-2 都消费既有学习项。排程不由模型设置，到期选择与单组上限以 schedule/领域常量为准。

SM-2 排程和各自完成交流需要跨重启保存；计时、动效、布局、滚动和模型在途进度均为临时态。删除或复核最后推进排程的证据时，按领域规则重建入口状态，不伪造不存在的完整复习历史。

## 7. 外部依赖与能力限制

### 教材

Tavily 沿用共享 Key/Base URL，Learning 的 [materials](../apps/learning/materials)拥有搜索、正文提取、来源索引和节选校验。原文由实际提取段落产生，教学改写另标来源；搜索摘要不能冒充原文。仅读取返回的安全公开网址；不提供任意文件或内网 fetch 能力。

课堂来源缓存只在运行内；已保存教材查看不重搜。缺配置、网页不可访问、限流或正文不足都明确报告，替换来源/自编需要符合产品约定。工具详情不显示搜索参数或原始正文，不因此声称实际外发内容的语义安全已经得到证明。

### 声音

TTS 拥有合成、音色配置和缓存，Learning 拥有自己的播放控制及听取条件。隐藏/卸载视图不持有音频资源唯一副本；停止、换课堂和迟到返回受所属运行保护。显式播放、慢放和重听不变成额外教学模型请求，也不改主聊天设置或清空其队列。

录音、转写和发音评估不在本轮实现内。不能从 TTS 或文字批改成功推断四项语言能力均已验证。

### 奖励

[rewards.ts](../apps/learning/application/rewards.ts)协调已确认完成、Economy 幂等入账、Learning 回执三步。发币失败不撤销学习完成，恢复只处理原资格；不把页面切换、回复到达或动效结束当作到账依据。

### 宿主

注册沿用 Learning module/descriptor/production module、Host/Shell catalog 和懒加载入口，不加入剧情维护 participant。兼容目标是 SillyTavern 1.14/1.18、现行浏览器/WebView 和实际供应商协议；推送正式线前必须启动 1.14 检查扩展加载，不用类型检查代替宿主运行证据。

## 8. 验证方式与交付边界

| 要证明的契约 | 最低有效层 |
| --- | --- |
| 阶段、批注、真实原答、SM-2 和证据删除 | 领域/应用语义测试 |
| 任务资料、工具许可、公开与隐藏内容 | 实际请求/工具执行边界测试 |
| 并发帮助、保存失败、未知写入与精确恢复 | 仓库和真实应用集成，保留失败收据 |
| 协议真实结束和停止后不发布 | 实际适配器/SDK 的固定传输测试 |
| 引用提问、逐句修订/跳过、入本、宽窄切换及焦点 | 正式组件浏览器操作；引用提问须经过真实 iframe/FrameBridge，不能用直接方法调用代替传输边界 |
| 非活动重视图释放、长内容切换和监听趋势 | 浏览器测量，区分桌面模拟与真实移动设备 |
| 教材适配、批改准确、范文等级、角色自然和泄题 | 授权真实模型样本及独立语义评审 |
| Tavily 实际可达、TTS 音质与设备播放 | 对应真实服务/设备验证，不能由本地模拟背书 |

常规检查：npm run test:xiaobai-os、npm run lint:xiaobai-os、变更 JS 的 ESLint、npm run lint:imports、npm run build:xiaobai-os、git diff --check。仅改变 TTS/Core 时补其对应检查，不越界重构。

隔离预览使用实际 Learning 组件、runtime 和内存仓库，Provider 仅给固定响应。它证明交互、状态和失败处理，不证明模型教学质量或真实新闻可获取。浏览器截图及临时探针放 output/playwright，不作为长期设计或验收日志提交。

真实付费模型/Tavily/TTS 调用需要明确的服务授权。未取得实际输出时，交付必须写“未验证”，不能用结构测试、HTTP 成功或固定脚本代替质量结论；同样不得把桌面 Chromium 检查冒充实体手机/WebView 验收。
