# 管理员 APP 终态设计

## 0. 状态与范围

状态：首版实现及本地交付检查完成。Host/Shell 入口、领域管理工具、独立会话及图片、流式 UI 已接通；真实模型验收因当前接口返回“无效的令牌”尚未通过，不能以隔离模拟测试代替。

管理员是 OS 本身应有的常驻 APP，不是任务异议流程，也不是后台维护失败后才出现的补救入口。用户可以直接与它沟通各 APP 的数据、记录和呈现问题，管理员查阅资料并执行获授权的修改。

实现遵循已确认的实施方案。现有任务后台维护的输入范围与自动调度没有因此扩大；管理员通过独立会话按需查阅原文。

## 1. 产品行为与权限

用户打开管理员即可聊天，无需先选问题类型或找到某个 APP 的纠错按钮。

| 用户意图 | 管理员行为 |
| --- | --- |
| 询问原因 | 读取有关记录和必要原文，解释核实到的情况；询问本身不等于允许改数据 |
| 指出记录有误、要求核查修正 | 查原目标、原记录与剧情事实，有依据后修正；不要求用户先自行整理全部证据 |
| 明确指定修改结果 | 按用户的管理指令处理，不再以剧情是否已经发生作为授权门槛 |
| 对象或修改含义不清 | 先读当前数据缩小范围，仍无法确定时再问一个必要问题 |

管理员的直接对话属于用户管理指令；它读到的任务、地图、世界资料和 RP 文本是资料，不会因为其中写了命令就获得管理权限。历史管理员回复和旧工具结果也不等于当前数据。

权限大于小白酒馆当前助手聊天的含义是：能实际修改已接入 APP 的业务数据，而非只能解释、建议用户手改。它不因“剧情应该怎样发展”拒绝用户明确的修改意图。

技术边界仍是普通 OS：通过 APP 提供的操作管理 OS 数据，不提供任意 JavaScript、文件系统或跨 APP JSON patch。小白酒馆的聊天产品可作行为参考，不能导入 Tavern DB、manager 或会话语义；第四面墙的皮下聊天也不是管理员。

## 2. 首批完整接入

| 所有者 | 首批管理能力 | 必须保持的领域边界 |
| --- | --- | --- |
| Tasks | 查任务与累计事实，核查原文，纠正进展，完成或判定失败当前 active 任务 | 判据引用[任务设计 §4.3](./tasks-app-target-design.md#43-活动任务)；状态与既有奖励结算一起提交 |
| Map | 查图册与场景，按用户要求纠正地点、连接、人物位置和场景布局 | 由 Map 编译空间操作并校验引用，管理员不直接改渲染器 |
| World | 查并修改世界概况、新闻与已有记录 | 当前 World 数据不等于 SillyTavern 世界书；不得声称已经修改角色卡或世界书 |

这些是首批实际工具，不是管理员永久只能管理三个 APP。其他 APP 按同一注册方式提供自身操作；未接入的操作明确说明当前不能执行，不给假成功。

任务终态重开、合同目标或报酬修改等超出现有命令的操作，需要先由 Tasks 定义对应领域事件与资金处理，再接入管理员；不能用直接改 status、余额或历史事件的通用工具绕过。首批不冒充具备这些能力，也不把底层暂缺操作说成用户没有权限。

## 3. 历史原文查阅

管理员需要程序提供的聊天搜索和分页读取，不让模型执行终端命令，不把整个长聊天一次性灌入上下文。

- 来源：当前 SillyTavern 聊天中当前选中的消息版本，包括普通用户与 Assistant 正文；不混入其他聊天或未选中的 swipe。
- 存储：直接读取宿主已有消息；不向聊天 JSONL 添加原文副本、搜索索引、向量或每楼标记。搜索结果只活在本轮运行内，管理员自身记录的保存位置见第 6 节。
- 搜索：按关键词或短语定位消息，返回命中片段、消息位置、说话人及继续查找位置。未命中只表示这次查询未命中，不等于事件没发生。
- 读取：按消息范围取原文；长消息支持继续读取，返回实际覆盖范围与截断信息。模型可以围绕搜索结果读取前后文，也能按范围顺读，不把关键词当唯一证据。
- 搜索按一个名字或短语做普通文字匹配，空格和标点按字面处理；多个线索分别搜索，未命中时缩短或换词。工具参数说明提供这条选词指导，不新增正则或中文分词能力。
- 初始上下文：当前聊天身份、已接入 APP 的能力目录、必要对象摘要和最近管理员对话；对象详情和旧原文按需读取。注入与读取使用同一投影，不保留两份不同形状的事实。
- 运行期间绑定聊天与消息快照；切聊停止旧工作，消息编辑或换 swipe 后重新核实已引用内容，避免按过期原文写入。长楼层续读沿用先前版本，不刷新旧依据；版本变化须从头重读。
- 引用原文时给用户可识别的消息位置和短摘录；后续原文已变更时，旧摘录只能作为当时查阅记录，不能冒充当前证据。

它只能依据实际读到的材料说明结论，不能把局部查阅包装成“查过全部历史”。现有维护只捕获接受轮，不因新增管理员自动获得历史搜索能力。

### 楼层编号契约

楼层号唯一依据是 SillyTavern 当前聊天 UI 的编号，从 `0` 开始；对应 `getContext().chat` 的原始数组下标。宿主 `public/script.js` 的消息渲染以 `messageId` 同时设置 `mesid` 和 `#${messageId}`，重排时也同步更新两者。

- 用户说“第 55 楼”或“#55”，读取的就是 `chat[55]`；工具参数、搜索结果、原文引用和界面展示沿用同一编号，不加减一。
- 筛选角色、跳过 system 消息或空消息、分页及只显示部分历史，都不能重新编号。不可读取或不存在的指定楼层应明确返回该状态，不能换成相邻楼层。
- 楼层号不是 JSONL 的物理行号，不计文件头或 metadata，也不是 Assistant 回复数、完整来回数或筛选后列表的序号。
- 读取范围两端均包含：55–57 楼就是 55、56、57。长消息的内部读取位置与楼层号分开，不能用一个含义不明的 offset 同时表示二者。
- 删除、插入或重排消息后，后续查询按当前宿主编号；已引用材料按本节的运行快照规则重新核实，不能把旧 #55 当成永久消息身份。

## 4. 终态结构与唯一事实来源

```text
apps/administrator
  对话、工具循环、运行状态、历史、UI
       │
       ├─ Agent capability：供应商会话
       ├─ 聊天原文读取适配：当前宿主聊天
       └─ 管理能力注册：路由到所属 APP
             ├─ apps/tasks：任务操作 → Tasks + Economy
             ├─ apps/map：地图操作 → Map
             └─ apps/world：世界操作 → World
```

- 管理员拥有自己的会话与交互，不拥有第二份任务、地图或世界数据。
- 各 APP 自带管理投影、领域说明、工具声明与执行入口；操作仍调用本 APP 的 application/domain 层。存在多个真实接入方后，共享注册层只做发现、路由与注销，不认识任务状态、地图字段或世界新闻。
- 聊天查阅最初服务管理员，先置于管理员的宿主适配内；出现第二个真实消费者后才提取通用能力，不预建虚拟文件系统、向量库或长期索引。
- 复用现有 Agent gateway、agent-core 协议适配、Kernel 事务和保存恢复，不新增供应商 SDK 或另一份 API 设置。
- 后台维护与管理员分别拥有提示词和调用流程。前者基于接受轮维护，后者回答用户并执行管理指令；只共享确实相同的领域操作，不能把 maintenance 的 manual 模式改名当管理员。

## 5. 执行、并发与失败反馈

一轮管理对话：理解意图 → 读取必要资料 → 调用对应操作 → 确认保存结果 → 回复用户。无需修改的询问在查证后直接回答，不为了展示工作而调用写工具。

工具结果区分读取成功、改动待保存、保存确认、失败和结果未确认。界面与模型使用同一个执行结果；文字说“已改好”不能替代写入回执。

每项写入使用所属 APP 的最新状态校验和既有事务能力。任务结算必须保持任务与资金原子；修改任务、地图、世界等多个独立对象不默认承诺全局一键回滚，部分成功需逐项说清。

世界按概况、新闻 ID 保留读取基线；地图按已读地点、连接、人物与场景保留基线，提交时检查目标及父级、端点、场景所有者等关联对象。读取另一对象不会刷新旧对象的依据；无关对象的新改动保留，不要求整个领域都回到同一旧版本。长资料续读也检查对应对象，不能拼接不同版本。

管理员修改会使同一对象上尚未提交的旧维护结果失效，提交前仍以 revision/预期内容校验拒绝覆盖。后续维护从已修正的当前记录出发；避免旧请求覆盖与模型今后仍可能误判是两件事，不能宣称 CAS 能永远阻止误判。需要长期保留的用户设定写入对应 APP 的事实，不靠管理员聊天充当隐形规则库，不新增永久全局锁。

取消阻止后续模型调用与未提交操作，不撤销已保存结果。提交已经发出时先确认其结果，再决定能否重试；重试不能重新发奖或重复执行已确认写入。

失败就在原对话保留原因和恢复操作。保存恢复分为「检查保存结果」「重新提交」「放弃未保存内容」：检查仅读回，重新提交执行 Kernel 随候选保留的原守卫，放弃保留服务器记录。首次创建且服务器确认文件从未存在时，放弃恢复未初始化状态；已有文件丢失仍视为冲突。停止或证据失效不妨碍确认已落盘结果，但所有 APP 的重新提交入口都不能绕过原守卫。维护的提交守卫只包含可重复检查的聊天、原文、启用和取消约束，一次性 session 状态及写入门控不混入恢复校验；保存未确认只停止后续维护，不等同主动取消。重载后读取真实 APP 状态，不把中断的请求自动重跑，也不从聊天中的成功文字推定写入成功。

同一工具调用身份只对应一条执行记录，准备回执失败与已派发业务结果未知分开处理。同一现场确认业务成功后直接补写对应回执，不调用模型；回执保存失败只恢复回执，不能重做业务。历史记录缺少可核验的运行凭据时保留当时的未确认状态；后续修改覆盖或核验失败返回明确核验结果，不阻断管理员打开、不重放旧写入。首次初始化前即建立临时发送生命周期，覆盖初始化、上传、用户消息保存和生成；同一现场确认后接续原发送一次，停止或停用使整个生命周期失效，重载不恢复。

同一运行现场的「重试」保留已完成工具与未完成步骤，先读回确认，再恢复未完成调用。重载或运行现场释放后，入口明确为「重新核查」：只读重新查证并回复，不重新执行不确定的旧写入；需要继续修改时由用户发起新管理指令。此边界避免为了跨重载重放而持久化执行队列。任务通过原业务事件确认是否已结算，地图与世界核对实际保存内容；后续修改取代旧请求时停止并询问，不覆盖现状。

## 6. 状态与生命周期

| 数据 | 所有者 / 范围 | 为什么保存或不保存 | 失败与删除 |
| --- | --- | --- | --- |
| 管理员对话、用户可见的操作结果记录及必要原文引用 | administrator / 当前聊天 sidecar 分区 | 用户重开后需要继续沟通；只保存可读记录，不保存 Provider 原始请求、隐式提示词或重复业务快照 | 保存失败保留当前可见内容并提示未保存；清空只删除管理员记录，不撤销 APP 修改 |
| 管理员历史摘要及其覆盖到的管理员消息身份 | administrator / 同一分区 | 重开后复用已经压缩的沟通历史，避免反复总结；是对话的派生材料，不是新的业务事实或授权 | 摘要与覆盖边界一起保存，失败保持旧版本；清空对话时一并清理，压缩本身不删除历史对话 |
| 当前输入草稿、流式片段、工具循环、取消信号、搜索结果及待提交修改 | 当前运行内 | 属于过程状态，不需要重启恢复 | 结束或切聊释放；未完成状态不伪装成成功记录 |
| 任务、地图、世界事实和资金 | 对应 APP / 原有作用域 | 沿用各 APP 唯一存储与不变量 | 由所属 APP 的恢复和删除路径处理，管理员不复制 |
| Provider 配置和已有全局设置 | 原有设置所有者 / 全局 | 不因管理员对话属于某个聊天而改变作用域 | 沿用现有设置入口与生命周期 |

对话记录只用于沟通连续性，重试依据真实业务状态与既有提交确认；不得为管理员另建永久执行队列或第二份业务账本。管理员记录保存与业务修改不是同一个成功概念：业务已保存而聊天记录保存失败时，明确区分，不能重做业务来补聊天。

会话、待保存候选、控制器操作和异步结果绑定发起时的聊天生命周期。切聊立即隔离旧状态；迟到的成功、失败或未确认不能回写新会话，已确认删除仍只清理原聊天附件。

聊天分支、重命名、删除沿用 OS sidecar 生命周期。清空对话与删除分区都需要用户明确操作；记录损坏只隔离管理员 APP，不静默清空、不阻断整个 OS。

管理员分区键为 `administrator`。图片使用宿主图片接口，存放在 `/user/images/xb-os-admin-${osId}/`，记录只保存路径与文件名。分支先复制到新聊天独占目录，再保存 sidecar；删除消息、清空、分区删除均先确认记录保存，再回收对应附件。未确认保存不提前删图，清理失败保留明确恢复入口。整个过程不向酒馆 JSONL 写入管理员正文或图片。

## 7. 界面

沿用信息 APP、第四面墙的聊天布局。按 frontend-design 的活动优先原则，主角是对话，不做管理表单墙。

- 桌面固定「管理员」入口；顶部为标题、上下文用量和清空聊天入口，中间为聊天记录，底部为输入栏。
- 上下文入口与计量展示按第 7.3 节；清空入口放顶部，点击后确认，删除范围按第 6 节，不混入业务数据清理。
- 点击消息显示就地操作：删除；管理员回复另有「重新生成」。不在每条消息下常驻操作栏，键盘与触屏都能打开；语义按第 7.5 节。
- 底部左侧直接选图，中间输入文字，右侧发送；可只发图片，也可附文字。发送前有缩略图和移除按钮，失败保留输入与附件供重试。当前模型不支持看图时明确说明，不静默丢图只发文字。
- 工具活动按第 7.1 节显示操作摘要，不在聊天中提供工具原始全文展开器。
- 成功结果保留简短回执；失败保留本条对话的重试或保存确认入口，输入不丢失。
- 其他低频操作放菜单；不常驻功能介绍、权限解释或每个 APP 的设置表单。
- 返回桌面或关闭面板不把已发出的写入说成取消；再次打开恢复当前进度。切换酒馆聊天遵循第 5、6 节边界。
- 窄屏、深浅主题、长消息、键盘焦点与触控操作须用真实组件验证；设计稿不算浏览器验收。

### 7.1 流式工具展示

用户需要看懂“正在查哪儿、准备改什么、结果如何”，不需要围观模型的工具协议。每次工具调用只展示：操作名称、有限的目标信息、执行状态，以及返回后的短结果或错误。展示数据从真实调用和执行结果派生，不解析模型说了什么来判断是否成功。

例如，查信件时先显示“搜索原文 · 伊莱、信件”，返回后显示命中数量；随后显示“读取 #55–#57”；修改时显示任务名称与保存状态。这些是界面交互示意，不是已存在的工具名或模型调用样例。

- 流式生成工具参数、工具实际执行、等待保存与保存确认分别展示，不能参数还没生成完就标成执行中。只消费已经可识别的目标信息，不逐 token 格式化整份参数 JSON。
- 进行中的操作就地更新，不能每收到一个片段就追加一条历史。完成后保留简短记录；同一轮的大量调用可折叠为操作列表，但读取全文从未进入这个列表。
- 面板只接收轻量展示投影，不通过 frame 消息把完整 Read 结果、全量地图、工具参数或 Provider payload 传给前端后再用 CSS 隐藏。折叠不等于懒加载，也不等于释放内存。
- 必须查看证据时，跳到对应酒馆楼层，或按需打开有分页上限的原文片段；关闭后卸载并释放。它是独立的证据查看，不是把全部工具返回铺在聊天里。
- 状态文案由集中定义的状态标识映射；不把错误原始 JSON 或堆栈当普通聊天内容。可见错误仍需说明具体操作和恢复方式。

### 7.2 渲染与内存预算

界面显示量、模型上下文量和持久历史量是三个不同边界，分别受控，不靠一个“最多显示多少条”掩盖其他两处的无限增长。

- 聊天每页 20 条，活动窗口最多 60 条，单条正文每块 4000 字符；操作列表每页 20 项，聊天只展示最多 6 项简短回执。向上翻页保持阅读锚点，不无限累积节点。
- 流式文本合并更新、节流渲染，只更新当前变化的消息或工具行；最终完成和失败状态及时刷新。不在每次流式回调中重做整段历史的 Markdown、语法高亮、JSON 序列化或全量快照传输。
- 用户向上阅读时不强制拉回底部；新内容用“回到最新”入口表达。面板隐藏后停止视图刷新；是否取消后台操作仍遵循第 5 节，不由渲染生命周期决定。
- 搜索按批处理并让出主线程，支持取消；结果有输出预算和继续位置。处理当前消息时不反复复制整个聊天，也不在每次重绘时重新搜索。
- 工具完整结果不持久化；当前会话现场的证据缓存最多 100 万字符，超限淘汰旧结果，失效时明确提示重新查阅。成功保存回复后释放模型协议与历史工作集；少量有界证据供本次详情查看，下一次运行或切聊释放，不额外建长期原文缓存。
- 上述限制保证的是新增传输、渲染和临时工作集可控，不声称宿主原有聊天数组或整个 sidecar 的加载成本已经消失。

### 7.3 模型上下文管理

参考信息 APP、教育 APP 的对话压缩方式，按完整交互而不是任意条数维护上下文。当前工具链与已归档对话分开：UI 不展示完整工具结果，不代表模型拿不到本轮所需证据。

- 每次模型请求前计入静态规则、工具定义、APP 投影、管理员历史、已有摘要及本轮工具结果；预算还需给回复与后续工具结果留余量。供应商原生 session 续接也必须管理已累积上下文，不能只算本次新发的消息。
- 搜索结果与 Read 从入口分页限量，不等溢出才把已经送进模型的全文隐藏。模型需要更多证据时继续读取，返回值明确实际范围，不能把截断片段当全文。
- 较大的工具结果由 `ToolResultRead` 按同一 reference 和连续 offset 续读，nextOffset 为 null 表示该结果已读完；原文自身的下一段仍由原工具读取。结果页不再次分页或复制入资料缓存，每次续读的详情仅在运行内引用原结果的对应范围，随原结果淘汰或运行释放一起失效。这些引用不进入聊天或 sidecar。
- 历史达到预算时，压缩较早的完整交互，保留当前用户请求、最近必要对话和未闭合工具链。不能拆散 tool call/result 配对；替换上下文时按供应商协议重建会话，不向旧会话假装发送了新历史。
- 摘要保留用户明确要求、已确认的修改、未解决问题、必要对象与原文定位，不塞入旧 Read 全文。它不扩展任务目标，也不能把一次操作扩大成永久授权；涉及当前业务事实仍重新读取所属 APP。
- 压缩成功且重新计量确实减少上下文后才替换摘要和边界；失败保留旧历史并明确反馈，不静默删聊天、不发送已知超出预算的请求。单轮本身过大时先减少读入范围或结束当前处理并说明，不能无限重试总结。
- 顶部上下文入口只显示用量圆环，不在圈内放数字，也不常驻用量文字；保留「上下文用量」可访问名称。圆环进度表示估算输入用量占管理员可用输入预算的比例；预算未知时显示未计量状态，不伪造进度。点开查看约用 token、预算及组成，整理历史时显示对应状态。只打开页面或翻阅历史不触发模型总结。
- 工作输入预算 64k、48k 开始整理，摘要输出预算 4k，当前图片另预留 6k；唯一策略定义为 `apps/administrator/domain/policy.ts`。这是应用预算，不是模型真实窗口。长历史分批按完整交互整理，摘要请求也受预算限制；供应商明确报告上下文超限时，收缩后最多自动重试一次模型请求，不重跑业务工具。

### 7.5 消息操作与图片边界

- 删除针对选中的管理员聊天消息，不顺带删除后续聊天，不撤销该轮已保存的 APP 修改。删除或重新生成涉及已摘要内容时，使受影响摘要失效并从保留记录重建，不能让已删内容继续由摘要带入模型。
- 「重新生成」只重新查证和回复：只提供读取工具，执行入口也独立拒绝写操作。新回复保存成功后一并更新正文、回复状态及错误，原业务回执不变；保存失败保留旧回复，不截断后续历史。原用户请求已删除时无法重新生成。失败操作恢复与此不同，遵循第 5 节。
- 历史窗口以会话 revision 为缓存边界，更新时刷新当前窗口并保留阅读锚点，不混合不同版本的行。消息内部分页以聊天、消息身份和 revision 定位，更新后重取当前页；旧请求迟到后不再回写。
- 对话删除、清空、重新生成不能与本会话进行中的操作并发；用户可先停止，已发出写入的结果确认仍按第 5 节处理。清空确认处简短说明不会撤销已完成的管理修改，不把这段说明常驻聊天页。
- 图片属于用户发送的管理员消息，不是生图功能。活动窗口内图片使用惰性加载和有界预览；图片输入计入第 7.3 节的模型预算，历史请求不反复附带 base64。支持 PNG/JPEG/WEBP/GIF，单张最多 4MB。
- 附件由管理员消息拥有，已发送图片随历史恢复，未发送图片只属于草稿。看图失败保留消息、附件与输入，不静默转成纯文字请求；回收规则见第 6 节。只有具体消息 ID 匹配时才重试原消息，上传失败且消息尚未创建则重新发送草稿；完成回调只清理由该次发送拥有的草稿版本，不清除后来编辑的文字或附件。

## 8. 提示词分层

实现按以下结构组织；共享规则位于 `apps/administrator/agent/prompt.ts`，领域块与工具由各 APP 提供。

1. 共享层：身份开头沿用电纸书的协作基调，交代 LittleWhiteBox／小白X 插件、小白 OS、SillyTavern 实例与管理员 APP 的关系，以及剧情外、当前聊天的工作范围；后续说明用户指令与读取资料的区别、查证与直接修改的决策、保存结果与回复边界。
2. APP 领域层：只补该 APP 的语义和决策，不各写一份管理员身份。任务判据引用任务自身定义，不另维护管理员版本。
3. 工具层：操作、返回形状、分页/容量和失败后的处理；参数语义放 schema，不在正文抄字段清单。
4. 资料层：当前 APP 投影、原文和工具结果；标明范围与截断，不将动态文本拼入可信规则。

实现时逐条对应实际能力；一个事实只写一处，其余引用或派生。判断核查与执行用户授权修改的区别由共享层表达，不给每个工具重复一大段禁令。

查证路线按用户提供的线索选择：指定楼层直接读取，事件或词句先搜索再读上下文；任务异议按原目标对照原文，明确管理修改按指令执行。回复以答案和实际结果为先，普通讨论不强制套操作汇报。任务、地图、世界在各自工具定义中共用参数与领域说明，维护和管理入口分别提供草稿／保存结果契约，不复制说明后追加覆盖。

## 9. 注册、兼容与删除

通过 `apps/administrator/module.ts`、独立分区和 Host/Shell catalog 接入；各 APP 随安装注册管理能力，释放时注销。某领域数据读取故障在初始资料中明确列为不可用，不拖死其他 APP 或管理员原文读取。

这是未上线的新功能，没有管理员旧 schema、旧入口或旧协议需要兼容。真正需要适配的是 SillyTavern 聊天与生命周期、浏览器/WebView、共享 Provider 协议和现行 OS 存储；不迁移 Tavern 管理员历史。

退场时取消未提交工作、确认已发出的保存，移除管理员目录、管理能力注册及两处 catalog，并在删除边界一次清理管理员分区和独占图片目录。已完成的业务修改属于原 APP，随管理员退场不会被撤销；不存在未结资金或需要永久保留的兼容壳。

## 10. 实施前核对与最小验收

所有权、唯一事实源、状态、依赖、注册、删除与兼容边界分别由第 4、6、9 节定义。本轮按用户确认的实施方案落地，不自动提交或推送。

| 必须保护的契约 | 最便宜的验证 |
| --- | --- |
| 长历史可定位、分页读完；未选中 swipe 不进入证据 | 聊天读取适配单测，覆盖长消息和继续位置 |
| 楼层编号遵守第 3 节，用户指定楼层不会偏移 | 适配单测核对 0、55、末楼与闭区间读取；覆盖筛选后保号、分页、消息删改和越界不替读 |
| 询问不会意外写入；资料里的命令不是用户授权 | 真实 Provider 场景验收；单测只验证角色和资料分层，不靠 Prompt 字符串断言冒充 |
| 管理调用走所属 APP；重复完成不重复发奖 | APP 管理入口与真实内存事务集成测试 |
| 切聊、编辑原文、并发维护不会提交过期结果 | Controller/服务边界集成测试 |
| 保存失败、未确认、部分成功可准确恢复 | 现有保存能力加管理员结果映射的集成测试，不跨层重复测全部存储实现 |
| 用户能直接沟通、查看修改与失败后继续操作 | 浏览器验证空态、长对话、工具执行、保存失败、返回及切聊 |
| 消息删除与重新生成不重复执行业务、不保留已删内容的旧摘要 | 会话边界测试覆盖已保存操作、历史回复、原请求被删、重生成失败及摘要失效；浏览器验证就地操作与清空确认 |
| 图片可单独发送或附文字，失败可恢复 | 附件边界验证保存与删除生命周期；浏览器验证选图、预览、移除、不支持看图及发送失败 |
| 工具全文不进入聊天展示与 frame 推送 | 投影边界测试用大体积 Read 结果验证传输仅含有界摘要；不以 DOM 折叠状态作为证据 |
| 长历史、密集工具和持续流式不会无限增加视图工作集 | 浏览器用长消息/长历史检查节点数、桥接负载、渲染次数与关闭后释放；同时验证上翻不跳底 |
| 上下文压缩保留请求、已确认结果及完整工具配对 | 请求组装与压缩边界测试，覆盖单轮过大、原生 session 续接、总结失败/无收益及不改变持久原文 |

真实使用样例至少包括：旧楼层已经交信却仍 active；旧进展擅自要求额外汇报；用户直接指定地图位置；更正世界记录；工具成功而后续模型回复失败；写入未确认后重试。自动任务维护仍应自行正确工作，管理员不能成为用户日常必须巡查的地方。

本轮未做：任务自动调度改造、任务终态及合同/报酬扩展、其他 APP 接入、Tavern 改造、新依赖、旧测试线格式兼容、提交和推送。真实 Provider 验收已尝试，但当前凭据无效，仍待有效配置后补验；不以提示词字符串断言或模拟模型宣称真实模型行为合格。
