# 管理员 APP 终态设计

## 0. 状态与范围

状态：设计稿，尚未实现。本文只确定普通小白 OS 的统一管理入口，不代表注册、工具、存储或界面已经交付；施工须另经用户确认。

管理员是 OS 本身应有的常驻 APP，不是任务异议流程，也不是后台维护失败后才出现的补救入口。用户可以直接与它沟通各 APP 的数据、记录和呈现问题，管理员查阅资料并执行获授权的修改。

本次先整理现有任务维护提示词并形成本文，不创建管理员运行时代码。现有任务维护的输入范围、重复运行守卫和工具能力没有因此扩大。

## 1. 产品行为与权限

用户打开管理员即可聊天，无需先选问题类型或找到某个 APP 的纠错按钮。

| 用户意图 | 管理员行为 |
| --- | --- |
| 询问原因 | 读取有关记录和必要原文，解释核实到的情况；询问本身不等于允许改数据 |
| 指出记录有误、要求核查修正 | 查原目标、原记录与剧情事实，有依据后修正；不要求用户先自行整理全部证据 |
| 明确指定修改结果 | 按用户的管理指令处理，不再以剧情是否已经发生作为授权门槛 |
| 对象或修改含义不清 | 先读当前数据缩小范围，仍无法确定时再问一个必要问题 |

管理员的直接对话属于用户管理指令；它读到的任务、地图、世界资料和 RP 文本是资料，不会因为其中写了命令就获得管理权限。历史管理员回复和旧工具结果也不等于当前数据。

权限大于小白酒馆当前助手聊天的含义是：能实际修改已接入 APP 的业务数据，而非只能解释、建议用户手改。它不因“剧情应该怎样发展”拒绝用户明确的修改意图。

技术边界仍是普通 OS：通过 APP 提供的操作管理 OS 数据，不提供任意 JavaScript、文件系统或跨 APP JSON patch。小白酒馆的聊天产品可作行为参考，不能导入 Tavern DB、manager 或会话语义；第四面墙的皮下聊天也不是管理员。

## 2. 首批完整接入

| 所有者 | 首批管理能力 | 必须保持的领域边界 |
| --- | --- | --- |
| Tasks | 查任务与累计事实，核查原文，纠正进展，完成或判定失败当前 active 任务 | 判据引用[任务设计 §4.3](./tasks-app-target-design.md#43-活动任务)；状态与既有奖励结算一起提交 |
| Map | 查图册与场景，按用户要求纠正地点、连接、人物位置和场景布局 | 由 Map 编译空间操作并校验引用，管理员不直接改渲染器 |
| World | 查并修改世界概况、新闻与已有记录 | 当前 World 数据不等于 SillyTavern 世界书；不得声称已经修改角色卡或世界书 |

这些是首批实际工具，不是管理员永久只能管理三个 APP。其他 APP 按同一注册方式提供自身操作；未接入的操作明确说明当前不能执行，不给假成功。

任务终态重开、合同目标或报酬修改等超出现有命令的操作，需要先由 Tasks 定义对应领域事件与资金处理，再接入管理员；不能用直接改 status、余额或历史事件的通用工具绕过。首批不冒充具备这些能力，也不把底层暂缺操作说成用户没有权限。

## 3. 历史原文查阅

管理员需要程序提供的聊天搜索和分页读取，不让模型执行终端命令，不把整个长聊天一次性灌入上下文。

- 来源：当前 SillyTavern 聊天中当前选中的消息版本，包括普通用户与 Assistant 正文；不混入其他聊天或未选中的 swipe。
- 搜索：按关键词或短语定位消息，返回命中片段、消息位置、说话人及继续查找位置。未命中只表示这次查询未命中，不等于事件没发生。
- 读取：按消息范围取原文；长消息支持继续读取，返回实际覆盖范围与截断信息。模型可以围绕搜索结果读取前后文，也能按范围顺读，不把关键词当唯一证据。
- 初始上下文：当前聊天身份、已接入 APP 的能力目录、必要对象摘要和最近管理员对话；对象详情和旧原文按需读取。注入与读取使用同一投影，不保留两份不同形状的事实。
- 运行期间绑定聊天与消息快照；切聊停止旧工作，消息编辑或换 swipe 后重新核实已引用内容，避免按过期原文写入。
- 引用原文时给用户可识别的消息位置和短摘录；后续原文已变更时，旧摘录只能作为当时查阅记录，不能冒充当前证据。

它只能依据实际读到的材料说明结论，不能把局部查阅包装成“查过全部历史”。现有维护只捕获接受轮，不因新增管理员自动获得历史搜索能力。

## 4. 终态结构与唯一事实来源

```text
apps/administrator
  对话、工具循环、运行状态、历史、UI
       │
       ├─ Agent capability：供应商会话
       ├─ 聊天原文读取适配：当前宿主聊天
       └─ 管理能力注册：路由到所属 APP
             ├─ apps/tasks：任务操作 → Tasks + Economy
             ├─ apps/map：地图操作 → Map
             └─ apps/world：世界操作 → World
```

- 管理员拥有自己的会话与交互，不拥有第二份任务、地图或世界数据。
- 各 APP 自带管理投影、领域说明、工具声明与执行入口；操作仍调用本 APP 的 application/domain 层。存在多个真实接入方后，共享注册层只做发现、路由与注销，不认识任务状态、地图字段或世界新闻。
- 聊天查阅最初服务管理员，先置于管理员的宿主适配内；出现第二个真实消费者后才提取通用能力，不预建虚拟文件系统、向量库或长期索引。
- 复用现有 Agent gateway、agent-core 协议适配、Kernel 事务和保存恢复，不新增供应商 SDK 或另一份 API 设置。
- 后台维护与管理员分别拥有提示词和调用流程。前者基于接受轮维护，后者回答用户并执行管理指令；只共享确实相同的领域操作，不能把 maintenance 的 manual 模式改名当管理员。

## 5. 执行、并发与失败反馈

一轮管理对话：理解意图 → 读取必要资料 → 调用对应操作 → 确认保存结果 → 回复用户。无需修改的询问在查证后直接回答，不为了展示工作而调用写工具。

工具结果区分读取成功、改动待保存、保存确认、失败和结果未确认。界面与模型使用同一个执行结果；文字说“已改好”不能替代写入回执。

每项写入使用所属 APP 的最新状态校验和既有事务能力。任务结算必须保持任务与资金原子；修改任务、地图、世界等多个独立对象不默认承诺全局一键回滚，部分成功需逐项说清。

管理员修改会使同一对象上尚未提交的旧维护结果失效，提交前仍以 revision/预期内容校验拒绝覆盖。后续维护从已修正的当前记录出发；避免旧请求覆盖与模型今后仍可能误判是两件事，不能宣称 CAS 能永远阻止误判。需要长期保留的用户设定写入对应 APP 的事实，不靠管理员聊天充当隐形规则库，不新增永久全局锁。

取消阻止后续模型调用与未提交操作，不撤销已保存结果。提交已经发出时先确认其结果，再决定能否重试；重试不能重新发奖或重复执行已确认写入。

失败就在原对话保留原因和恢复操作。模型请求失败可重试或继续说明；保存未确认时复用 Kernel 的读回确认；冲突时重新读取并核对。重载后读取真实 APP 状态，不把中断的请求自动重跑，也不从聊天中的成功文字推定写入成功。

## 6. 状态与生命周期

| 数据 | 所有者 / 范围 | 为什么保存或不保存 | 失败与删除 |
| --- | --- | --- | --- |
| 管理员对话、用户可见的操作结果记录及必要原文引用 | administrator / 当前聊天 sidecar 分区 | 用户重开后需要继续沟通；只保存可读记录，不保存 Provider 原始请求、隐式提示词或重复业务快照 | 保存失败保留当前可见内容并提示未保存；清空只删除管理员记录，不撤销 APP 修改 |
| 当前输入草稿、流式片段、工具循环、取消信号、搜索结果及待提交修改 | 当前运行内 | 属于过程状态，不需要重启恢复 | 结束或切聊释放；未完成状态不伪装成成功记录 |
| 任务、地图、世界事实和资金 | 对应 APP / 原有作用域 | 沿用各 APP 唯一存储与不变量 | 由所属 APP 的恢复和删除路径处理，管理员不复制 |
| Provider 配置和已有全局设置 | 原有设置所有者 / 全局 | 不因管理员对话属于某个聊天而改变作用域 | 沿用现有设置入口与生命周期 |

对话记录只用于沟通连续性，重试依据真实业务状态与既有提交确认；不得为管理员另建永久执行队列或第二份业务账本。管理员记录保存与业务修改不是同一个成功概念：业务已保存而聊天记录保存失败时，明确区分，不能重做业务来补聊天。

聊天分支、重命名、删除沿用 OS sidecar 生命周期。清空对话与删除分区都需要用户明确操作；记录损坏只隔离管理员 APP，不静默清空、不阻断整个 OS。

## 7. 界面

按 frontend-design 的活动优先原则，主角是对话，不做管理表单墙。

- 桌面固定「管理员」入口；页面以聊天记录和底部输入框为主。
- 工具活动在对话中显示短状态，必要时展开原文引用、操作对象和结果；不是整屏 JSON 或冗长思考过程。
- 成功结果可打开对应 APP；失败保留本条对话的重试或保存确认入口，输入不丢失。
- 清空历史等低频操作放菜单；不常驻功能介绍、权限解释或每个 APP 的设置表单。
- 返回桌面或关闭面板不把已发出的写入说成取消；再次打开恢复当前进度。切换酒馆聊天遵循第 5、6 节边界。
- 窄屏、深浅主题、长消息、键盘焦点与触控操作须用真实组件验证；设计稿不算浏览器验收。

## 8. 提示词分层

此处仅约定结构，不提前写尚无工具实现支撑的完整 system prompt。

1. 共享层：管理员身份、用户指令与读取资料的区别、查证与直接修改的决策、保存结果与回复边界。
2. APP 领域层：只补该 APP 的语义和决策，不各写一份管理员身份。任务判据引用任务自身定义，不另维护管理员版本。
3. 工具层：操作、返回形状、分页/容量和失败后的处理；参数语义放 schema，不在正文抄字段清单。
4. 资料层：当前 APP 投影、原文和工具结果；标明范围与截断，不将动态文本拼入可信规则。

实现时逐条对应实际能力；一个事实只写一处，其余引用或派生。判断核查与执行用户授权修改的区别由共享层表达，不给每个工具重复一大段禁令。

## 9. 注册、兼容与删除

实施时使用 `apps/administrator` 的 module、独立分区和 Host/Shell catalog 接入；各 APP 自行注册/注销管理能力。依赖故障仅使相应管理操作不可用，不拖死其他 APP 或管理员的全部只读能力。

这是未上线的新功能，没有管理员旧 schema、旧入口或旧协议需要兼容。真正需要适配的是 SillyTavern 聊天与生命周期、浏览器/WebView、共享 Provider 协议和现行 OS 存储；不迁移 Tavern 管理员历史。

退场时取消未提交工作、确认已发出的保存，移除管理员目录、管理能力注册及两处 catalog，并在删除边界一次清理管理员分区。已完成的业务修改属于原 APP，随管理员退场不会被撤销；不存在未结资金或需要永久保留的兼容壳。

## 10. 实施前核对与最小验收

开工前的所有权、唯一事实源、状态、依赖、注册、删除与兼容边界分别由第 4、6、9 节定义。先完成各 APP 管理接口与恢复协议的施工方案，再确认开工；不以本文自动授权实现。

| 必须保护的契约 | 最便宜的验证 |
| --- | --- |
| 长历史可定位、分页读完；未选中 swipe 不进入证据 | 聊天读取适配单测，覆盖长消息和继续位置 |
| 询问不会意外写入；资料里的命令不是用户授权 | 真实 Provider 场景验收；单测只验证角色和资料分层，不靠 Prompt 字符串断言冒充 |
| 管理调用走所属 APP；重复完成不重复发奖 | APP 管理入口与真实内存事务集成测试 |
| 切聊、编辑原文、并发维护不会提交过期结果 | Controller/服务边界集成测试 |
| 保存失败、未确认、部分成功可准确恢复 | 现有保存能力加管理员结果映射的集成测试，不跨层重复测全部存储实现 |
| 用户能直接沟通、查看修改与失败后继续操作 | 浏览器验证空态、长对话、工具执行、保存失败、返回及切聊 |

真实使用样例至少包括：旧楼层已经交信却仍 active；旧进展擅自要求额外汇报；用户直接指定地图位置；更正世界记录；工具成功而后续模型回复失败；写入未确认后重试。自动任务维护仍应自行正确工作，管理员不能成为用户日常必须巡查的地方。

本文未做的工作：管理员实现、聊天历史工具、任务调度/重复守卫改造、任务终态及资金协议扩展、其他 APP 接入、Tavern 改造、真实 Provider 或浏览器验收。
