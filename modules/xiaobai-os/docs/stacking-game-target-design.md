# 云上叠叠屋：进入 OS 的终态

日期：2026-09-28。用户授权按目标文档、施工文档、初审、实现、终审完成。本文承接最后确认的“可玩性 + 可持续收获”，替代此前免费且仅首达发币的提案。施工见 [施工与初审](./stacking-game-implementation-plan.md)，证据见 [验收与终审](./stacking-game-verification.md)。

## 产品合同

现有游戏大厅中的独立 3D 技巧游戏，不增 OS 主屏应用。云海、圆润奶色房屋、吊车、小住户和亮灯营造小白质感。每局最多 20 间，目标节奏约 3～5 分钟；这不是强制倒计时。玩家通过调头与落下，在移动吊车下决定落点、控制偏心和后续承托。画面是 3D，输入固定在左右平面；搭建镜头跟随楼顶，结算可看全楼、旋转缩放、导出图片。

房型只有宽底、窄阁楼、阳台偏心、错台四类。承托轮廓必须在模型中真实可见，重量/偏心可辨认；当前房屋与下一间预告可见。烟囱、小住户、晾衣绳不参与碰撞；不做阳台黏连、隐藏挂钩或随机倒塌率。每个承托面按其上全部重量的重心检验，轻微危险仍允许下一间配重救回。下落投影只说明落点，不直接给安全答案。

前四间慢速且较宽，但错误落点从第一间就会输；5～10 间加入偏心；11～15 间窄平台、错台组合；16～20 间混合房型、较快吊运。房序与起始吊运相位由种子确定，生成有预算且必须得到一条完整合法的 20 间建成路线。只保证开局可解，不保玩家的任意旧决定可救。不搞突然大风或临时改重量，不按玩家赢钱暗调难度。

## 持续收益与结束

- 报名扣 50，题目认证失败或余额不足不收费。费用与开局同事务确认。
- 成功安放 8/12/16 间后分别可收工到账 50/80/120；在两门槛之间收工取已达到的最高档。阶段奖金不逐项累加、不提前入钱包。
- 20 间自动通关，到账 200。每局都能兑奖，不限首通、不设每日次数或收益上限。
- 落空、承托不足、任一承托面失稳会失败；失稳前稳住的建筑仍可留影。失败或主动放弃不发奖、不退报名费，没有撤回、复活、免费换题。
- 继续搭就是拿本局尚未结算的奖金承担风险；收工/满楼与到账原子提交。允许熟练玩家合理获利，不宣称防止一切盈利。上线前实测简单策略、落点误差、不同收工策略的到达率和局时，不能用算法代替真人胜率。

运行时金额、房型、几何、曲线和资源预算均单点定义于功能内 policy/house 规格，本文是产品合同，不再在其他文档抄参数作为第二事实源。

## UI、声音与渲染

画面主角是吊车和楼。顶栏是已搭间数、当前可收工金额；底栏是当前/下一间房型、调头、落下，达到门槛再出现收工。费用和不可逆后果放在报名/放弃确认中；有未结束局优先继续。结算展示整栋楼、实收与净收益、再开局和留影入口，最高间数及最佳建筑可回看。说明收纳在规则弹层，不做长说明首页。

落稳有下落/回弹、窗灯点亮和住户反馈；危险、失败、收工/满楼有区别的音效，默认开，可关闭。声音偏好保存到 Game 的独立 stacking 设置，音频实例只活在页面内，浏览器首次手势后启动；保存失败明确显示，离开暂停/销毁，不把偏好改成关。

默认清透且抗锯齿。固定最大房屋数、共享几何材质、总渲染像素与阴影预算优先防止资源失控；持久过载才请求有限画质降档，在非落点操作的边界应用，不逐帧重建 Renderer，不影响输入时钟/规则。画质档位为临时态，不存用户档案。不承诺自适应能杜绝崩溃。隐藏、收起、离开停止绘制；图形错误明确暂停，恢复原局，不暗换题、不降级成别的游戏。尊重减少动态效果与两倍文字。

## OS 生命周期与资金

局属于用户而非聊天：关闭、刷新、换聊天均恢复同一种子、动作和收据。吊运暂停，不因离开倒塌；已发出的落下必须先复核，不能恢复后重选。单次动作含身份和版本；Host 验证位置、朝向、状态、付款和真实规则，不接收客户端奖励/胜利宣告。重复请求不重扣重奖，未知写入保留同候选并先复核；切聊天后的已接受提交仍可恢复。

终审补充：现有用户事务协调器的候选只在 Host 内存中。叠叠屋因此自有一条本地待确认操作记录（`recovery.ts`），以已付费局的唯一 ID 和版本绑定，在发出落点/收工/放弃前写入。它不是第二份游戏存档，不保存楼体、钱包或声音；确认完成或读取到已替换/清除的局后删除。整个 Host 重启后先读服务器，再复核同一操作，不能对另一局重放。本站存储不可用时明确阻止新操作；清除此功能时删除该本地键和用户分区。该记录解决意外刷新，不作为防止主动篡改浏览器的反作弊系统。

## 开工前八项边界

1. 所有者：`apps/game/stacking/` 自有领域、生成、存储、钱包协议、Host/client、UI/3D/声音/文案。不是搬家类型，原三款 GameKind 不扩展。
2. 唯一事实：规则/房型/金额集中；关卡按种子生成；楼体与奖金从确认的动作和收据派生；画面复用规则的承托几何，不另算一份碰撞。
3. 持久态：独立用户分区保存当前种子/动作、防重身份和财务收据；保存一个已结束旧局的最佳建筑以跨重启回看。当前局被新报名替换前，才按纪录规则晋升归档；不同时维护重复的最高分计数。最佳建筑新纪录替换，完整用户数据清理时删除；财务审计与钱包一致。相机、吊运运行时相位、动画、图形档位、音频上下文临时。声音偏好归 Game 设置，沿其统一保存/失败处理/清理路径。
4. 外部依赖：已有 Three.js/Vue、PartitionStore、Economy；不引入物理引擎、模型 API、外部素材下载或 AI 提示词。
5. 注册入口：Game 模块 additional partition/service/runtime 组合、独立游戏大厅条目、Game 声音设置。核心层没有叠楼语义。
6. 删除路径：删 stacking 目录与少量注册/设置键，一次清理所属用户分区；既有钱包审计交易保留，不倒扣已发奖励。
7. 兼容对象：SillyTavern、本项目当前设置/用户文件边界、浏览器/WebView。没有叠叠屋历史用户数据，不建旧 schema/API 兼容壳。保留用户改过的搬家声音和画质，不改无关工作区内容。
8. 最少测试：规则/生成/渲染预算纯逻辑；真实用户事务测费用、分档、重复、拒绝/未知恢复；client/设置测声音保存与身份切换；生产组件浏览器测操作/结束/续玩/留影/生命周期/资源/触屏/窄屏；现有类型、lint、全 OS 测试与构建。

## 不做及完成门槛

不做自由建城、多人榜、无限楼层、装修商城、首通一次后无收益、收费复活、暗中控制输赢。不能拿可编译方块、模拟钱包、只验一条成功路线或过时截图冒充交付。实际实现必须证明落点错会输、配重真有用、四房型改变决定、所有发奖可重入恢复；必须看生产画面、走真实桥接的胜负与资金，并如实报告性能/真人测评边界。速度/容差/动画可在此合同内依据实测调校，不擅自改模式、收费或奖励。
