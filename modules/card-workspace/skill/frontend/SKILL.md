# 小白X卡片前端

前端是玩家读故事、看场景、做操作的地方。你按这张卡的玩法安排它：先想清楚玩家怎样玩，再选做多重，最后才写代码。卡的设定、世界书和写回读 ReadSkill builtin-card-files；数值和结算读 builtin-state3，已有 2.0 卡读 builtin-state2。

## 先走一遍玩家的路

动手前，把玩家的一轮游玩从头说一遍：从哪里进入 → 看到什么场景、读到什么正文 → 能做哪些事 → 做完之后谁回应、结果是什么 → 接下来能去哪。界面上放的是此刻发生的事和玩家此刻能做的事，不是变量清单。

一张只有数值和按钮的面板，玩家不知道故事在哪、自己是谁、为什么要点。正文、场景、操作要连在一起：玩家点了"接待"，就该读到接待的过程；读完知道下一步可以做什么。

## 两种玩法

**聊天卡**：玩家说一句，AI 回一楼，一楼一楼往下走。前端把每一楼的文字排成画面，可以带场景图、对白样式和按钮。历史就是聊天记录，删楼、swipe 时变量跟着回到对应位置。

**固定界面的卡**：玩家一直在同一个界面里玩，比如放在开场楼的网页，或盖在酒馆上的全屏桌面。界面自己显示正文和场景，玩家在里面行动。

固定界面不等于不能用变量，也不等于必须离开聊天。它可以有三种做法，开工前和用户定下来：

| 做法 | 怎样运转 | 要额外负责的 |
| --- | --- | --- |
| 界面里的操作仍发成聊天消息 | AI 照常回楼，界面读最新楼和变量来显示 | 基本没有，酒馆保存一切 |
| 界面自己调用 AI 生成，状态用小白X变量 | 生成文字用 `callGenerate`，数值通过变量接口提交 | 对话历史要自己存；同一楼里点了很多次，变量不会按每次点击分楼回退 |
| 界面自己生成、自己存档 | 卡自己保存每回合的正文和状态 | 存在哪、按哪个聊天或存档分开、刷新后怎么恢复、失败了哪步已生效、怎样撤销和清除，全都由卡负责 |

要注意：开场楼里的网页，编辑、swipe、换聊天、刷新页面都会重建，页面里的 JS 变量随之消失，它不是存档。浏览器本地存储不会随角色卡导出，也不跟着删楼回退。

## 选多重的前端

| 档位 | 做法 |
| --- | --- |
| 无前端 | 正常文字聊天；需要变量时只做初始化与提示词 |
| 轻量展示 | 约定格式 + 显示正则，替换成酒馆净化后的 HTML（无脚本） |
| 中等交互 | 约定格式 + 显示正则，替换成 HTML 代码块，由小白X渲染为楼层 iframe，可读变量、带脚本与按钮 |
| 重型应用 | 循环任务挂常驻应用，玩家主要在应用里操作；读[重型前端参考](<../references/xiaobaix-heavy-ui.md>) |

聊天卡大多停在轻量或中等：让 AI 按约定格式写，正则把这段文字换成画面。约定格式时：

- 用卡自己的标签，不依赖预设的标签。预设可能有显示正则先改写文本，也可能在整理历史时剥掉标签；核对预设后再定标签名。
- 格式要能被正则稳定匹配：开闭标签成对、不嵌套同名标签、生成中断时未闭合的文本照常显示。
- 楼层 iframe 在生成结束后才渲染，流式过程中显示的是原文。
- 数值从变量读，不让 AI 每楼重抄一遍状态栏。

旧楼层是当时发生的事。操作台只放在最新一楼时，旧楼留下能读的文字，不让每个旧楼都跟着最新数值变。

图片与档位独立：无图、自备素材、运行时绘图或混合均可。场景图跟着地点和情境走，临时出场的人物不必都有立绘；没有图时，正文和操作照样能玩。见[媒体接口](<../references/xiaobaix-capabilities.md#media>)与[素材节](<../references/xiaobaix-heavy-ui.md#assets>)。

## 在哪里执行代码

| 位置 | 适用寿命 | 读取方式 |
| --- | --- | --- |
| 显示正则 | 随楼层；正文美化 | 经宿主 HTML 净化，无脚本 |
| 楼层 HTML 代码块 | 随楼层；本楼显示与交互 | 同源 iframe；宿主公开 API 从 `window.parent` 访问 |
| 循环任务 `<<taskjs>>` | 后台动作或跨楼层常驻界面 | 运行于酒馆页面，使用 `window`、`document`、`SillyTavern.getContext()` |

触发时机、停止条件、iframe 寿命见[能力参考](<../references/xiaobaix-capabilities.md>)第 2～4 节。常驻任务重跑先卸载旧实例，登记 `onCleanup`。图片、地点表等大块共享数据由任务挂到父页面一份，各楼 iframe 从 `window.parent` 取，取不到时只少那一块；带 iframe 的正则用 `maxDepth: 0` 只给最新一楼。

## 按这个顺序做

1. 拿一段像样的正文和一个真实行动，先把画面排出来，桌面和手机都看：正文读得顺吗，下一步一眼能找到吗。
2. 接上 AI：聊天卡发消息，固定界面按上面选定的做法生成。发送前保留玩家写到一半的草稿；生成中、失败、取消都让玩家看得到。按钮发消息见[发送说明](<../references/xiaobaix-capabilities.md#message-buttons>)。
3. 需要数值时接变量，显示实际提交后的结果；刷新页面不会再结算一次。面板怎样跟着变量更新见[变量刷新](<../references/xiaobaix-capabilities.md#state-panel-refresh>)。
4. 接图片和语音。服务失败时保留已有结果，不自动重复付费请求。
5. 按[交互验收](<../references/xiaobaix-capabilities.md#frontend-validation>)实际点一遍：重开、切聊天、编辑和 swipe、连点、生成中点、保存失败、没有图片。截图好看和没有报错，都不等于能玩。
