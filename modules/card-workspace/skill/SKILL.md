# 小白X角色卡制作

你在小白助手的角色卡工作区里组织角色设定、世界书与提示词，并按需要接入小白X（LittleWhiteBox）的变量、任务与前端。目标是把用户需要的内容写回当前卡，能继续边用边改。已有卡的无关任务、正则、世界书和玩家数据保留原样。

## 开始工作

通过 CardFiles open 取得当前卡目录，先读与需求有关的已有文件。编辑使用助手原有的 Read、Grep、Write、apply_patch；CardFiles save 只接收要写回的文件路径。本文末尾的文件操作说明给出实际布局。

用户在同一工作区可以看到、编辑和继续修改文件。内容可以分次写回，未完成脚本也能保存；写回不执行脚本或改动聊天变量。运行检查与保存是两件事，检查发现问题就继续修改，不要求用户一次写对。

## 先想清楚玩家怎样玩这张卡

做整张卡或大改玩法前，先把这张卡讲成一段玩家经历，用几句话和用户对齐，再动文件：

- 玩家以什么身份进来，想在这里做成什么事；世界里谁会回应他、怎样回应。
- 开场时玩家看到什么场景、读到什么、第一步能做什么；做完之后接着能去哪里、做什么。日常里的几件事彼此相连，不只是几个菜单名。
- 哪些人和设定固定，哪些人物和事件随情境出现；哪些事由玩家拍板，哪些要对方也愿意。
- 哪些结果要可靠地记住或计算，交给变量；哪些留给角色扮演自由发挥。行动次数、固定步骤、输赢条件只在玩法确实需要时才加。

用户已经说过的就从对话里提取，不让用户重新填一遍。参考别的卡时，借的是体验和做法，人物、画风和数据结构按这张卡自己的设定来。还没和用户确认的设计是提案，写清楚哪些是你补的。用户说"不好玩""看不懂"时，先判断问题出在玩法、设定、呈现还是代码，再改那一层。

## 先组织模型会读到什么

新建卡、拆分世界书、调整蓝绿灯或提示词层次时，先读[提示词组织](<references/prompt-organization.md>)。先按其中的内容骨架归位，再决定放在哪个载体、什么时候进入请求、怎样控制先后，以及怎样检查实际展开结果；小白X的变量与前端能力在这个基础上接入。只修按钮或脚本时，直接读对应能力参考。

## 小白X的两条制作原则

**前端呈现故事，也承载玩家的操作。** 玩家读到的正文、看到的场景、能点的按钮，都由前端安排。聊天卡里，每条回复是一个新楼层，前端把这一楼的文字排成画面；固定界面的卡里，玩家留在一个界面里读和做。具体怎么选、怎么做，读 ReadSkill builtin-card-frontend。

**变量是当前的完整状态。** 小白X变量保存最新的全部状态，删楼、swipe 时自动回到对应位置。前端和模型随时读到最新的全部值，AI 只交变化，不重复输出全部状态。制作时按下文的变量一节选择变量版本。

## 变量

新卡要用变量时，默认推荐变量 3.0，先读 ReadSkill builtin-state3。简单卡开放字段直接修改，复杂玩法使用动作、派生值、修正和触发规则。维修已有卡时沿用当前版本；已有 2.0 卡先读 ReadSkill builtin-state2。交付时写明所用模式，由玩家在小白X设置里选择。

两个变量技能负责结构、初值、更新规则和前端读写；世界书、开场白和提示词仍按本技能组织，界面按前端技能做。变量 3.0 里改变状态的后果写进规则与触发；结算成功后播放声音、通知等使用卡内“结算成功后”脚本。依据变量值选择世界书内容时，读[条件规则 `<varevent>`](<references/xiaobaix-capabilities.md#varevent>)。

## 写入哪些卡工程产物

角色任务、正则、世界书与卡字段按本文末尾的文件布局编辑，写回由 CardFiles 完成。更新已有任务沿用原 ID。工作区中的辅助笔记不是运行时可访问的网址；前端代码要放进可写回的正则替换内容或完整任务脚本。

交付包括本次实际需要的格式规则、正则、HTML、任务与变量初始化，以及启用条件（所用的变量模式、循环任务开关、允许卡内正则），不替玩家改全局设置。

## 怎样证明做完了

- 先按开场走一遍玩家会做的事：能不能看懂处境、知道下一步做什么，角色有没有回应，行动结果有没有进到后面的故事里。
- 检查 JSON、JS 与正则的语法；正则用真实楼层文本（含预设保存的格式）核对匹配与替换。助手的 RunJavaScriptApi 在当前酒馆页面里执行普通异步 JavaScript，可读写真实页面和聊天状态，会改动状态的代码按权限模式确认；它不提供 Node、文件系统或命令行。只报告实际执行过的检查。
- 世界书看预期条目是否真的进了请求、宏展开成了什么。
- 变量与前端各按自己的技能验收。
- 写回回执不等于任务已经运行，也不等于真实酒馆联调通过。运行会改变玩家状态时，在隔离聊天验证，交付时说明实际检查到哪一步：已写回、检查已过、酒馆里联调已过，还是已经实际玩过。
- 确认可复用的故障原因后，可记入助手工作记录；本技能随插件发布，不是用户可写的 skill 文件。尚未查实的猜测不写成接口事实。

[解铃会](<../../variables/state3/skill/references/examples/jieling.md>)是一张随插件附带的变量 3.0 示例卡：故事里接待来访者、旁听互助、听汇报，面板上分室、处理事件、结束一周。学变量结算时读它；它的面板很朴素，前端怎么做看前端技能。
